# Лучший язык для программирования с AI по токенам/скорости/памяти

## Кратко

Ведущий проводит шуточный эксперимент: ИИ-агент через OpenCode и недорогую модель DeepSeek пишет одну и ту же CLI-утилиту на Rust, Go, Java и Python, которая ищет топ-10 фильмов в большом CSV с рейтингами. Сравниваются время работы, пиковая память, размер кода и расход токенов, а не качество кода. По замерам Rust быстрее всех, затем Go, Java и Python; Python, по словам ведущего, тратит в несколько раз меньше токенов. Ведущий шутит, что Python почти идеален, но сам признаёт, что выводов нет. Спорно: код не ревьюили, корректность смотрели поверхностно, спецификация не требовала скорости, а каждую реализацию написали один раз. Числа в расшифровке местами искажены, поэтому их стоит сверять по таймкоду.

## Разделы

### 1. Вступление и задача эксперимента — 00:00:02–00:01:05
Ведущий благодарит за комментарии, напоминает, что выпуски выходят уже 25 дней подряд, и просит подписаться. Выпуск он называет экспериментальным и скорее развлекательным, хотя доля правды в нём есть. Задача: одна небольшая CLI-утилита на нескольких языках и сравнение по токенам, объёму кода и другим метрикам примерно за 20 минут. Зрителей он просит повторить эксперимент и написать свои результаты, особенно о том, меняет ли это выбор языка.

### 2. Инструмент и выбор модели — 00:01:05–00:02:38
Код пишет OpenCode, открытый инструмент, к которому подключаются разные модели. Opus ведущий отбрасывает: непонятно, сколько токенов он тратит, и он слишком умный, поэтому сравнение будет неинтересным. Берётся модель среднего уровня, DeepSeek 4.1 Flash, по подписке OpenCode Go примерно за 10 долларов, которую ведущий советует тем, кому не хватает денег на Claude или ChatGPT. Подписку он выбирает и ради бюджета: через OpenRouter раньше ушло около 100 долларов на эксперименты.

### 3. Выбор языков и задача — 00:02:38–00:03:39
Языки выбраны так: Rust, потому что всё переписывают на него; Java, потому что канал про Java; Go, который считают простым; и Python, на котором пишут очень много кода. TypeScript и Node.js исключены из-за нехватки времени, а будущее Node.js ведущий называет неясным, хотя фрагмент расшифровки здесь искажён. Задача: CLI-утилита читает большой CSV-файл, где записано, кто, какому фильму и какую оценку поставил и когда, и выводит топ-10 фильмов.

### 4. Запуск агентов и спецификация — 00:03:39–00:07:50
Задача сначала уходит на Rust в первую папку, затем в отдельных окнах OpenCode запускаются Go, Java и Python. Ведущий следит за счётчиком токенов и отмечает, что файл с рейтингами весит около 700 МБ. Производительность в спецификации не оговаривается: ни прогрев JVM, ни настройки CPython не обсуждаются. Спецификация задаёт параметры (число фильмов, минимум голосов, пути к файлам), запрещает зависимости и просит алгоритм рейтинга IMDb. Код ведущий решает не проверять и полагается на модель; к концу отрезка Rust и Python готовы.

### 5. Сравнительный скрипт и разбор кода — 00:07:50–00:10:25
Ведущий запускает ещё одну сессию, которая пишет скрипт сравнения: каждый кандидат запускается по 10 раз, и сравниваются время, память и объём кода. Времени мало: по его оценке, пять минут на двадцатиминутный ролик, а агент сам находит сессии, что ведущего удивляет. Код он смотрит на ходу: Rust кажется очень заумным, с дженериками и отдельной хэш-таблицей, Python — один файл около 225 строк, Java — около 400 строк, а версия Java осталась неизвестной.

### 6. Результаты, тесты и размер кода — 00:10:25–00:12:59
Go оказывается единственным языком с тестами, хотя о тестах в спецификации не было ни слова, и ведущий этому удивляется. По минимальному и медианному времени порядок такой: Rust, Go, Java, Python. Пиковая память, по его словам, около 50 МБ у Rust, 27 МБ у Go и 200 МБ у Java; почему у Java так много, он не знает, а по Python цифр в расшифровке нет. Метод замера памяти он не проверял и предполагает, что её берут из вывода команды time. Строк кода примерно 800 у Go (по контексту), 700 у Rust, 400 у Java и 200 у Python.

### 7. Токены и итоговая шутка — 00:12:59–00:15:32
У Rust, по его восклицанию, около миллиона токенов, у Java около 1,5 млн на 400 строках, у Python около 200 тысяч на 200 строках; цифры Go путаются. Связь строк и токенов он находит закономерной, но деньги сравнивать трудно. Корректность он смотрел поверхностно, и по Java, как он говорит, с ней не вышло. Выпуск вышел на 23 минуты вместо 20, выводов нет, и ведущий спрашивает зрителей про выбор языка. Полушутя Python назван почти идеальным: он в шесть и более раз медленнее Rust и Go, но тратит в пять раз меньше токенов.
