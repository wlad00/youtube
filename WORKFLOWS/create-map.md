# «Создай карту» — прогрессивная ручная карта ролика

Эта инструкция является обязательным продолжением `AGENTS.md` для трёх полностью эквивалентных команд:

- «Создай карту»;
- «Создай раздел»;
- «Создай первый раздел».

Во всех трёх случаях поведение одинаковое: **как только готов первый законченный смысловой раздел, немедленно сохранить его в GitHub и сообщить пользователю, что раздел 1 готов; затем без новой команды продолжить обработку ролика до полной карты.**

Не путать с «Создай разделы» / «Нарежь разделы»: эти команды остаются отдельным скриптовым процессом через `sections.yaml` + `tools/materialize_sections.py`.

## Цель

Минимизировать не полное время обработки ролика, а **время до начала содержательного обсуждения**. Пользователь должен иметь возможность открыть `sections/01.md` в параллельном чате, пока текущий исполнитель продолжает читать и размечать остальной ролик.

Одновременно с нарезкой формируется компактная поисковая карточка ролика в его `README.md`, чтобы позже выбирать ролики и находить нужные темы без повторного чтения всех расшифровок.

## Вход и ограничения

1. Основной и обязательный вход — `transcript.cleaned.md` в папке ролика.
2. Если файла нет, не подменять эту команду скриптовой нарезкой. Сначала должен быть выполнен обычный этап скачивания/очистки субтитров.
3. `tools/materialize_sections.py` для этой команды **не использовать**: ни для определения границ, ни для создания `sections/*.md`.
4. Читать текст последовательно с начала и не перечитывать уже обработанную часть без необходимости.
5. Границы ставить по завершению мысли/аргумента. Технический размер файла и равная длительность разделов вторичны.
6. Перед закрытием раздела прочитать небольшой запас вперёд, достаточный для уверенности, что мысль действительно закончилась. Не публиковать заведомо предварительный `sections/01.md` только ради скорости.
7. Существующий блок `review` в front matter `README.md` сохранять без изменений.

## Прогрессивный проход

### 1. Первый раздел — приоритет

1. Начать с `00:00:00` и читать `transcript.cleaned.md` только до первой надёжной смысловой границы с необходимым запасом контекста.
2. Выбрать короткое содержательное название.
3. Создать `sections/01.md` вручную. В нём должны быть:
   - заголовок раздела;
   - ссылка на источник `../transcript.cleaned.md`;
   - интервал времени;
   - полный текст очищенной расшифровки, относящийся к этому интервалу, без пересказа и без заметок обсуждения.
4. Сразу добавить первый подтверждённый раздел в `## Разделы` файла `README.md`. Пока весь ролик не прочитан, не придумывать будущие разделы.
5. Немедленно сделать commit+push первого раздела и обновлённого `README.md`.
6. Сразу сообщить пользователю: `Раздел 1 готов: <название> — <интервал>.` Если среда позволяет выдавать промежуточный статус, не прерывая выполнение, продолжить работу сразу после этого сообщения. Если среда возвращает управление пользователю после сообщения, первый раздел всё равно должен быть уже сохранён; при следующем продолжении не начинать заново.

### 2. Остальные разделы

1. Продолжить с точной границы конца предыдущего раздела.
2. Каждый следующий файл `sections/NN.md` создавать тем же способом, сохраняя непрерывность интервалов.
3. Не возвращаться к началу ролика для повторного полного чтения: смысловой проход должен оставаться одним последовательным проходом.
4. После раннего commit первого раздела остальные разделы можно собрать в один финальный commit, если пользователю не нужен потоковый доступ к каждому из них.

## Что записывать в README.md

README — единая карточка ролика и место durable-результатов его обсуждения. Не плодить отдельные `NOTES.md`, `QUESTIONS.md` и `SOURCES.md`, пока объём не потребует этого.

Во время и после построения карты поддерживать следующие секции:

### `## Коротко`

2–5 предложений о том, что реально разбирается в ролике. Заполнять только по прочитанному тексту; окончательно обновить после полного прохода.

### `## Темы`

Короткий список основных тем и подтем, пригодный для быстрого просмотра.

### `## Разделы`

Подтверждённые смысловые разделы по порядку: название, интервал и ссылка на `sections/NN.md`. Во время прогрессивного прохода секция может быть частичной; непрочитанный остаток не размечать.

### `## Основные тезисы`

Кратко зафиксировать главные утверждения автора после полного прохода. Не превращать в подробный конспект.

### `## Для поиска`

Имена, понятия, книги/места Писания, события, устойчивые термины и полезные синонимы, по которым этот ролик потом имеет смысл искать.

### `## Обсуждение`

Создавать только когда реально появились результаты разговора. Хранить не стенограмму чата, а durable-результат по разделам: выводы, уточнения, открытые вопросы и проверенные источники. Формат:

```md
## Обсуждение

### Раздел 1
- Вывод: ...
- Вопрос: ...
- Источник: ...
```

Если обсуждения ещё не было, пустой раздел не нужен.

## Завершение карты

После чтения всего ролика:

1. Проверить, что интервалы `sections/NN.md` непрерывны, начинаются с `00:00:00`, не перекрываются и последний раздел заканчивается концом расшифровки.
2. Создать или заменить финальный `sections.yaml` с теми же границами и названиями. Последний `end` — `END`.
3. Окончательно обновить `README.md`: `Коротко`, `Темы`, полный список `Разделы`, `Основные тезисы`, `Для поиска`.
4. Поставить `structure_status: ready` и заполнить `tags` только подтверждёнными по содержанию тегами.
5. Синхронизировать соответствующую строку `INDEX.md` с `README.md` и подтверждёнными тегами.
6. Не изменять `review`.
7. Сделать финальный commit+push всех оставшихся изменений.

## Инварианты

- Все три команды «Создай карту», «Создай раздел», «Создай первый раздел» выполняют **один и тот же полный процесс**; формулировка не ограничивает работу одним разделом.
- Первый законченный раздел всегда является первым durable checkpoint и публикуется раньше полной карты.
- `sections/*.md` содержат только исходный текст соответствующего смыслового интервала и служебный заголовок/интервал; аналитика и результаты обсуждения живут в `README.md`.
- Не выдумывать темы, тезисы, теги или будущие разделы по названию ролика.
- Не смешивать эту команду со скриптовой «Создай разделы».
