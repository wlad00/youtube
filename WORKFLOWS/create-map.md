# Создание смысловых разделов

Эта инструкция обязательна для всех эквивалентных команд:

- «Нарежь разделы»;
- «Создай разделы»;
- «Создай карту»;
- «Создай раздел»;
- «Создай первый раздел».

У всех команд один результат и одна семантика. Разница между средами только техническая: **если доступен `tools/materialize_sections.py`, файлы режет скрипт; если скрипт недоступен, модель создаёт те же файлы сама.**

## Главный принцип

Цель — быстро получить надёжные первичные фрагменты для обсуждения, а не заранее пересказать ролик.

- Модель читает `transcript.cleaned.md` последовательно и сама определяет смысловые границы.
- Названия разделов должны быть короткими и описательными, без выводов и оценки.
- Границу ставить на временную метку строки `transcript.cleaned.md`, с которой начинается новая мысль: скрипт режет по строкам этого файла, поэтому скриптовая и ручная материализация дают одинаковый результат.
- `README.md` содержит только навигацию: название раздела, интервал, ссылку.
- Никаких «Коротко», «Сути», тезисов, вопросов или подробных описаний при создании разделов.
- `INSIGHTS.md` этой командой не создавать и не читать.

## Источники при дальнейшем обсуждении

`sections/NN.md` — первичный рабочий источник соответствующего раздела. Чтобы обсуждать раздел, агент должен открыть и прочитать этот файл. `README.md` недостаточен для ответа о содержании.

`INSIGHTS.md` — вторичные выводы прежних обсуждений. Его не читать автоматически. Открывать только по явному смыслу запроса: продолжить прежнее обсуждение, вспомнить выводы, учесть накопленные заметки. Он никогда не заменяет проверку первичного `sections/NN.md`.

## Прогрессивный проход

### 1. Подготовка

1. Найти папку ролика.
2. Основной вход — `transcript.cleaned.md`. Если его нет, сначала выполнить обычный этап скачивания/очистки субтитров.
3. Не строить границы по названию ролика, старому README или `INSIGHTS.md`.

### 2. Первый раздел — ранний checkpoint

Только когда скрипт недоступен и в задании один ролик. Если скрипт доступен (для одного ролика тоже) или роликов несколько, этот этап пропустить: без `--partial`, без отдельного коммита и сообщения о первом разделе — каждый ролик сразу проходить целиком (этапы 3–4) и сохранять одним коммитом.

1. Читать от `00:00:00` до первой надёжной законченной мысли, затем прочитать небольшой запас вперёд, чтобы убедиться в границе.
2. Выбрать короткое название.
3. Записать в `sections.yaml` только подтверждённый первый раздел с явным конечным таймкодом, не `END`.
4. Вручную создать `sections/01.md` из полного текста `transcript.cleaned.md` внутри того же интервала и синхронизировать минимальный блок `## Разделы` в `README.md`.
5. Сделать commit+push `sections.yaml`, `README.md` и `sections/01.md`.
6. Сразу сообщить пользователю: `Раздел 1 готов: <название> — <интервал>.`
7. После этого без новой команды продолжить обработку оставшейся части ролика.

Если среда не умеет после промежуточного сообщения продолжать работу в фоне, первый раздел всё равно должен быть уже сохранён в GitHub; продолжать с его конечной границы при следующем запуске, не перечитывая начало без необходимости.

### 3. Остальные разделы

1. Продолжать последовательно от конца первого раздела, а если этап 2 пропущен — от `00:00:00`.
2. Для каждого нового подтверждённого раздела добавлять в `sections.yaml` название, `start` и явный `end`.
3. Отдельных коммитов для последующих разделов не делать: всё собирается в финальный commit.
4. Если скрипта нет, вручную создавать `sections/NN.md` с тем же форматом и исходным текстом интервала.

### 4. Финал

1. После прочтения конца ролика заменить `end` последнего раздела на `END`.
2. Проверить непрерывность: первый `start` = `00:00:00`, конец каждого раздела равен началу следующего.
3. Если скрипт доступен, запустить обычную финальную материализацию без `--partial`:

```bash
python tools/materialize_sections.py "<папка ролика>"
```

4. Если скрипта нет, вручную закончить `sections/*.md` и минимальный `## Разделы` в `README.md`.
5. Не менять `structure_status`, `tags` и `review` только из-за создания разделов.
6. Не создавать `INSIGHTS.md`.
7. Сделать финальный commit+push (при нескольких роликах — один коммит на ролик).
8. В отчёте по каждому ролику указать: число разделов и чем созданы `sections/*.md` — скриптом или вручную; если вручную, назвать причину, по которой скрипт не удалось использовать.

## Формат раздела

`sections/NN.md` содержит только служебный заголовок и первичный текст:

```md
# 1. Короткое название

Источник: `../transcript.cleaned.md`  
Интервал: `00:00:00 --> 00:08:30`

[00:00:00] ...
```

Никаких выводов, комментариев, вопросов, тезисов или ссылок на `INSIGHTS.md` внутри файла раздела.

## INSIGHTS.md

`INSIGHTS.md` — отдельный файл для результатов **реального последующего обсуждения**, а не этапа нарезки. Создавать или дополнять его только когда пользователь просит сохранить выводы либо когда в обсуждении явно принято сохранить durable-результат.

Писать кратко и привязывать к разделу, например:

```md
# Insights

## Раздел 2
- Краткий вывод, который действительно был получен в обсуждении.
- Открытый вопрос, если он остался.
```

Не копировать туда весь разговор. Не использовать этот файл как доказательство того, что сказано в ролике.
