# DeepSeek Harness - НЕ убийца Claude Code. Все поняли его неправильно

## Кратко

Автор, который записывает курсы по веб-разработке, объясняет, что такое харнес: языковая модель сама по себе только получает и отдаёт текст, а харнес даёт ей инструменты, память, субагентов и скилы и крутит цикл вызова инструментов, пока задача не решена. Его главный тезис: большинство обзоров показывают только веб-панель DeepSeek Harness, тогда как суть в открытости и сборке всего поведения из плагинов, то есть в конструкторе, а не в готовом продукте вроде Claude Code, где обвязка вшита. Автор показывает установку, подключение моделей через агрегаторы, оплату по токенам, режимы-пресеты и плагины. Вывод: это не убийца Claude Code или Codex, а отдельная категория, вроде Linux рядом с macOS, полезная тем, кто настраивает агента под себя или встраивает его в свой продукт. Спорно: сравнение с macOS и Linux и утверждение, что других агентов с такой кастомизацией нет, автор не проверяет; подписку через другие сервисы он не тестировал, а идею о заточенности под встраивание назвал почти теорией заговора.

## Разделы

### 1. Что такое харнес — 00:00:00–00:03:40
Автор объясняет, что языковая модель сама по себе только получает и отдаёт текст, действий не совершает. Чтобы из чата получился агент, модели передают описание инструментов, она называет нужный вызов, система его выполняет, а результат возвращается в модель, и так по кругу, пока задача не решена. Всю эту обвязку, то есть инструменты, память, субагентов и скилы, он называет харнесом и сравнивает с упряжкой для лошади. Раздел задаёт базу для всего видео: без этого отличие агента от обычного чата не видно. Определение дано на уровне схемы, без кода.
Файл: sections/01.md

### 2. Харнес как конструктор: macOS, Linux и открытый код — 00:03:40–00:07:18
Автор сравнивает Claude Code с macOS: всё работает из коробки, и менять почти ничего не хочется. DeepSeek Harness он называет Linux, то есть конструктором, где настраивается практически всё. Исходники открыты на GitHub, ядро минимально, а всё поведение, включая интерфейс, собирается из плагинов, которые можно заменить на свои. По его словам, у других агентов обвязка вшита в продукт и правится только через скилы, MCP и подобные надстройки. Главный тезис ролика: большинство обзоров показывают лишь веб-панель и упускают эту суть.
Файл: sections/02.md

### 3. Запуск, десктоп и вход в аккаунт — 00:07:18–00:13:36
Веб-интерфейс запускается одной командой в PowerShell с подтверждением, а можно клонировать репозиторий, если хочется править код. Автор выбирает первый путь и предупреждает, что продукт в превью и возможны ломающие изменения. Затем он ставит десктопное приложение для macOS и Windows и входит в аккаунт DeepSeek по почте, без подтверждения телефона, с небольшим бонусом на баланс. Посреди раздела идёт отступление: автор рекламирует свой курс по веб-разработке на 80 с лишним уроков и говорит, что ролики о безопасности на YouTube собирают меньше просмотров, чем ролики о Claude Code. Это не про продукт, но автор использует это как довод о выборе тем.
Файл: sections/03.md

### 4. Подключение моделей и провайдеров — 00:13:36–00:19:16
В веб-версии провайдеров моделей подключают в настройках: из списка или кастомного, с указанием base URL. Автор добавляет два агрегатора: Polza AI, доступный в России и пополняемый российскими картами, и OpenRouter с пополнением криптой. По ходу он ошибается с base URL, найденным через поиск, и после исправления список моделей загружается. Довод в пользу двух провайдеров практический: доступность сервисов зависит от VPN, поэтому проще переключить провайдера. Раздел заканчивается выяснением, что аккаунт DeepSeek работает по балансу за токены, а не по подписке; подписку через другие сервисы, например OpenCode Go, автор лишь предполагает, сам её не пробовал.
Файл: sections/04.md

### 5. Режимы-пресеты: Standard, PTC, Minimal, Creator — 00:19:16–00:24:58
Четыре режима автор называет пресетами: это наборы плагинов, доступных агенту в сессии. Standard ведёт себя как обычный агент вроде Claude Code или Codex, Minimal оставляет только терминал и годится для сравнения моделей без чужой обвязки, а PTC обещает объяснить позже. В Creator агент может сам править плагины и конфигурацию, и автор упоминает, что так можно создать свой режим, например review без правок файлов, но показ откладывает до следующих разделов. Вывод раздела: режим задаёт, какие инструменты видит модель, а не только стиль ответа.
Файл: sections/05.md

### 6. Плагины: встроенные, маркеты и доверие — 00:24:58–00:33:15
В сессионных плагинах у Minimal шесть, у Standard двадцать девять, у Creator тридцать; глобальных около ста восьмидесяти шести, и они обеспечивают работу ядра и интерфейса. Из официальных плагинов автор включает автоматические задачи, где задача по расписанию создаётся прямо из чата, и ставит тестовый плагин-питомец через npm. Готовые плагины он ищет в каталогах сообщества на GitHub (по словам автора, около 18 тысяч) и на стороннем сайте, ставит командой DSH с указанием профиля desktop или web либо через маркет плагинов. Пример с канбан-доской он выбирает по числу звёзд и предупреждает, что в плагинах возможен вредоносный код, поэтому нужно доверять проверенным репозиториям или читать код.
Файл: sections/06.md

### 7. Настройка без кода: правила, скилы, конфиг, хуки — 00:33:15–00:37:55
Первый уровень не требует кода: правила лежат в файле agents.md в корне проекта или в пользовательской папке для всех проектов, а скилы в папках skills. Слэш-команды автор предлагает делать из скилов: отключить автоматическое подключение и вызывать вручную. Второй уровень это YAML-конфиг профиля, где уже записаны провайдеры и можно прописать MCP-сервер через официальный плагин MCP-клиента. Хуки из Claude Code подключаются отдельным плагином, а нативный хук тоже оформляется как плагин с той же логикой. Автор честно признаёт, что проще поручить эту настройку самому агенту, чем править файлы руками.
Файл: sections/07.md

### 8. Свой режим, субагенты и типы плагинов — 00:37:55–00:43:03
Свой пресет можно добавить через конфиг или поручить Creator. Тестовый режим review без инструментов записи действительно не смог править файл: агент ответил, что записи у него нет, и предложил готовый текст в ответе. Затем автор рассказывает о встроенных субагентах: глубину вложенности и число параллельных запусков можно настроить, по умолчанию, по его словам, стоят значения 1 и 8, а субагентов Claude Code и Codex подключают плагинами. Плагином можно сделать нативный хук, слэш-команду с любым кодом, инструмент через MCP и виджеты интерфейса; по просьбе в Creator агент сам добавит вкладку статистики или кнопки-подсказки.
Файл: sections/08.md

### 9. Веб-версия как движок внутри приложения — 00:43:03–00:48:12
Автор предлагает аналогию: веб-версия харнеса — сервер, который обслуживает панель и выполняет действия, как сервер обычного веб-приложения. Когда разработчик встраивает агента в свой сервис, модель по API отдаёт только текст, и весь цикл разбора инструментов, запуска действий и возврата результатов приходится писать с нуля. По мнению автора, харнес позволяет взять этот цикл готовым и встроить в продукт. Он замечает, что в документации почти нет про веб и десктоп, а раздел разработки плагинов большой, и допускает, что продукт заточен под встраивание; сам он называет это почти теорией заговора. Раздел подводит к демонстрации.
Файл: sections/09.md

### 10. Устройство изнутри: плагин, бандл, профиль, PTC — 00:48:12–00:55:27
Автор описывает четыре уровня без кода. Плагин может быть одним файлом и даёт инструменты, слэш-команды, обработку событий или правки промпта. Бандл собирает плагины со своим конфигом, а профиль (например, web или desktop) это упорядоченный список бандлов, где порядок важен; при запуске поднимается процесс с этой конфигурацией. Базовые бандлы: DSH Base с ядром, журналом, циклом агента и песочницей, DSH Web App с интерфейсом, DSH Headless для командной строки и DSH SDK App для встраивания, где агентом управляет код приложения. Затем автор возвращается к PTC: модель пишет код, который вызывает инструменты, и в контекст возвращается только итог, что не всегда короче обычных вызовов.
Файл: sections/10.md

### 11. Демо: агент внутри аналитики продукта — 00:55:27–00:58:32
Автор показывает демо-приложение: статистика SaaS-продукта и окно агента, который запускается внутри функции кода на базе харнеса. У агента есть инструменты чтения базы данных, построения графиков и таблиц. На вопрос о росте оттока на тарифе Starter он выдаёт гипотезы, опираясь на отзывы пользователей, и среди них называет повышение цены. Автор признаёт, что описание того, на чём основан ответ, могло бы быть подробнее, а качество ответов не измеряет. Смысл раздела: обвязку берут готовой и не пишут цикл вызова инструментов с нуля.
Файл: sections/11.md

### 12. Итоги: убийца или нет — 00:58:32–END
Автор подводит итоги: харнес крутой, но нужен не всем, и это не убийца Claude Code или Codex, а другая категория, как Linux рядом с macOS. Для личного использования он полезен тем, кто хочет всё настроить; тем, кому нужна работа без возни, автор советует более готовые агенты, например Claude Code. Главный довод в пользу харнеса: для встраивания агента в свой продукт он удобнее, и автор не знает других агентов с такой кастомизацией. Напоследок автор предлагает разобрать код отдельно, если это интересно зрителям, и рассказывает, что демо собрано с помощью Claude по документации.
