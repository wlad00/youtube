# AGENTS.md

Репозиторий с YouTube-роликами, очищенными расшифровками и навигацией для последующего обсуждения.

## Главная модель

Один ролик = одна папка = один основной текстовый источник.

    <коллекция[/подколлекция...]>/<ГГГГ-ММ-ДД-slug-названия>/
      README.md
      transcript.cleaned.md
      INSIGHTS.md          # опционально, только выводы реального обсуждения
      chunks/              # опциональный технический fallback для очень больших файлов

Если известен только месяц публикации — ГГГГ-ММ-slug-названия.

У старых роликов могут оставаться дополнительные файлы, поля и блоки прежнего формата. Не удалять их автоматически и не строить на них новый рабочий процесс.

### transcript.cleaned.md

transcript.cleaned.md — обязательная цельная очищенная расшифровка и единственный первичный источник содержания ролика.

У подготовленного ролика файл имеет три слоя:

    ## Кратко

    - 5–8 коротких тезисов обо всём ролике.

    ## Навигация

    - 00:00:00 — Короткое название смыслового блока
    - 00:07:30 — Следующая тема

    [00:00:03] Полный текст расшифровки...
    [00:00:33] ...

Кратко и Навигация — вторичная карта для ориентации. Они не заменяют полный транскрипт. Конкретные факты, формулировки, аргументы и контекст при ответе всегда проверять по тексту ниже.

Подготовленным считается ролик, у которого в transcript.cleaned.md есть оба блока: ## Кратко и ## Навигация.

### README.md

README.md хранит метаданные ролика, а не пересказ.

Новый front matter:

    ---
    title: ""
    youtube: ""
    video_id: ""
    date: ""
    collection: ""
    language: ""
    tags: []
    ---

Ниже front matter — заголовок ролика. Не помещать туда Кратко, навигацию, пересказ, тезисы или выводы.

Если в старом README уже есть неизвестные/legacy-поля или блок review, сохранять их без изменений, если текущая команда прямо не относится к ним.

### INSIGHTS.md

INSIGHTS.md — опциональный файл для durable-выводов реального обсуждения. Не создавать его во время скачивания или подготовки ролика и не использовать как замену транскрипту.

Открывать его только когда пользователь просит продолжить прошлое обсуждение, вспомнить прежние выводы или сохранить новые выводы.

## INDEX.md

INDEX.md — единый каталог роликов. Первичный поиск по коллекции, названию, описанию и тегам начинать с него.

Таблица:

    | Дата | Ролик | YouTube | Коллекция | Субтитры | Подготовлен | О чём | Теги |

Правила:

- Субтитры = да, если существует transcript.cleaned.md.
- Подготовлен = да, только если в transcript.cleaned.md есть и ## Кратко, и ## Навигация.
- О чём — одно короткое предложение, полученное после чтения всего транскрипта. До подготовки ставить —.
- Теги берутся из tags в front matter README.md. До подготовки могут быть —.
- Источник истины — файлы ролика; если INDEX расходится с ними, исправлять INDEX по файлам.
- Новые ролики добавлять сверху по дате.

В начале INDEX находится список коллекций с короткими описаниями.

## Основные команды

Перед изменениями в локальной сессии выполнить:

    git pull --rebase origin main

Правки могут прийти из другой сессии или через GitHub.

### 1. «Прими ролик: <ссылка>»

Ссылку можно заменить названием, автором, примерной датой, фразой из ролика или другими однозначными признаками.

Если ссылки нет, искать YouTube через yt-dlp:

    "$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe/yt-dlp.exe" --simulate --print "%(title)s | %(channel)s | %(upload_date)s | %(id)s" "ytsearch10:<запрос>"

Если совпадение одно — брать его. Если кандидатов несколько — показать название, канал, дату и ID и дать выбрать.

Дальше:

1. Получить название, каноническую ссылку, Video ID и дату публикации.
2. Выбрать коллекцию по теме; при неоднозначности использовать unsorted/, не останавливая работу.
3. Создать папку ролика и README.md по новому шаблону.
4. Добавить строку в INDEX.md: Субтитры — нет, Подготовлен — нет, О чём — —, Теги — —.
5. Commit + push.

На этом шаге не придумывать содержание по одному названию.

### 2. «Скачай субтитры: <ролик>»

1. Найти папку по video_id, ссылке или названию.
2. Скачать только оригинальную дорожку; машинный перевод не использовать.
3. Записать фактический язык оригинала в language README.
4. Из сырого SRT обязательно создать transcript.cleaned.md с дедупликацией rolling captions и сохранением таймкодов.
5. Удалить сырой subtitles.*.srt после успешного создания cleaned-файла.
6. Не создавать автоматически Кратко, Навигацию, INSIGHTS.md или chunks/.
7. В INDEX.md поставить Субтитры — да; оставить Подготовлен — нет, если аналитическая подготовка ещё не выполнялась.
8. Commit + push.

Это дешёвый технический ingestion. Он не должен автоматически читать и анализировать весь ролик.

### 3. «Подготовь ролик: <ролик>»

Эквивалентные команды:

- «Подготовь ролик»
- «Подготовь к обсуждению»
- «Подготовь видео»

Это одна универсальная команда для Desktop app и ChatGPT.com.

Алгоритм:

1. Найти папку ролика.
2. Проверить наличие transcript.cleaned.md.
3. Если его нет:
   - в локальной/Desktop-среде, где доступен yt-dlp, сначала выполнить шаг «Скачай субтитры»;
   - в среде без локального доступа к yt-dlp не выдумывать содержание: сообщить, что сначала нужно получить cleaned-транскрипт.
4. Прочитать весь transcript.cleaned.md от начала до конца.
5. Создать или обновить ## Кратко:
   - 5–8 коротких тезисов;
   - покрыть весь ролик, а не только начало;
   - это карта содержания, не самостоятельный источник фактов.
6. Создать или обновить ## Навигация:
   - смысловые границы, а не равные интервалы;
   - для длинного ролика обычно 8–20 якорей, для короткого меньше;
   - каждый пункт: точный таймкод начала + короткое название;
   - при необходимости добавить одну короткую подсказку.
7. Полный текст расшифровки ниже не переписывать.
8. Выбрать примерно 3–8 полезных тегов и записать их в tags README.
9. Сформулировать одно короткое предложение О чём для общего INDEX.
10. Обновить строку INDEX: Субтитры — да, Подготовлен — да, заполнить О чём и Теги.
11. Commit + push.

Команда идемпотентна: повторный запуск обновляет существующие блоки и метаданные, а не создаёт дубликаты.

Не создавать отдельные файлы по смысловым разделам.

### 4. «Прими и подготовь ролик: <ссылка>»

Универсальный полный pipeline:

    принять → скачать оригинальные субтитры → очистить → прочитать целиком →
    Кратко → Навигация → теги → О чём → обновить INDEX → commit + push

В Desktop/local выполнять целиком.

В ChatGPT.com, если transcript.cleaned.md уже есть в репозитории, команда начинает с аналитической подготовки. Если транскрипта ещё нет и локальный yt-dlp недоступен, остановиться только на недостающем техническом шаге и явно это сказать.

### Голая ссылка без команды

Голая ссылка на YouTube означает:

    Прими ролик + Скачай субтитры

То есть ролик регистрируется и cleaned-транскрипт создаётся, но полный аналитический проход автоматически не запускается.

Если пользователь хочет всё за один раз, он говорит: «Прими и подготовь ролик».

## Обсуждение ролика

Основной источник — цельный transcript.cleaned.md.

Когда пользователь начинает содержательно обсуждать ролик:

1. Открыть его transcript.cleaned.md.
2. Если есть ## Кратко и ## Навигация, использовать их как карту.
3. Если одного из этих блоков нет, один раз предложить: «Ролик ещё не подготовлен к обсуждению. Подготовить?»
4. Не блокировать разговор: если пользователь хочет ответ сразу, работать по полному транскрипту без подготовки.
5. Для конкретного вопроса найти нужный якорь и прочитать соответствующий фрагмент полного транскрипта плюс достаточный контекст до/после.
6. Не отвечать на конкретные фактические вопросы только по Кратко или Навигации.
7. Для вопросов, связывающих начало, середину и конец ролика, использовать навигацию для быстрого перехода между несколькими фрагментами, затем сверять каждый по первичному тексту.

## review — состояние кураторской проработки

В front matter README может присутствовать блок review, который ведёт Куратор ATLAS. Это отдельная ответственность.

    review:
      stage: discussed
      state: open
      sessions:
        - date: "2026-09-12"
          turns: 12
          minutes: 35
          insights: 3

Обычные команды YouTube-pipeline не создают, не удаляют и не нормализуют review. Если он существует, сохранять его без изменений.

## Неотсортированные ролики

unsorted/ — временная коллекция для роликов, у которых тематическая коллекция неочевидна. Сомнение не должно останавливать ingestion или подготовку.

Перенос из unsorted/ — отдельная команда: переместить папку и в том же коммите поправить путь и колонку Коллекция в INDEX.

После основной команды, если в unsorted/ есть ролики, можно одной строкой напомнить, сколько их ждёт распределения.

## Скачивание субтитров

yt-dlp установлен через winget, но его почти никогда нет в PATH. Не проверять yt-dlp --version; запускать по явному пути.

Сначала узнать код оригинальной дорожки:

    & "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe\yt-dlp.exe" --list-subs "<ссылка>"

Найти строку вида ru-orig  Russian (Original). Маска *-orig в версии yt-dlp 2026.07.04 была сломана, поэтому использовать явный код языка.

PowerShell:

    & "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe\yt-dlp.exe" --skip-download --write-auto-subs --write-subs --sub-langs "<lang>-orig" --convert-subs srt --no-progress --ffmpeg-location "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.FFmpeg_Microsoft.Winget.Source_8wekyb3d8bbwe\ffmpeg-N-125875-g5d4d3bdc61-win64-gpl\bin" -o "<папка ролика>/subtitles.%(ext)s" "<ссылка>"

Bash:

    "$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe/yt-dlp.exe" --skip-download --write-auto-subs --write-subs --sub-langs "<lang>-orig" --convert-subs srt --no-progress --ffmpeg-location "$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.FFmpeg_Microsoft.Winget.Source_8wekyb3d8bbwe/ffmpeg-N-125875-g5d4d3bdc61-win64-gpl/bin" -o "<папка ролика>/subtitles.%(ext)s" "<ссылка>"

--ffmpeg-location обязателен.

После скачивания файл обычно имеет вид subtitles.<язык>-orig.srt; переименовать без -orig.

PowerShell:

    Get-ChildItem "<папка ролика>\subtitles.*-orig.srt" | Rename-Item -NewName { $_.Name -replace '-orig\.srt$', '.srt' }

Bash:

    for f in "<папка ролика>"/subtitles.*-orig.srt; do mv "$f" "${f%-orig.srt}.srt"; done

Затем создать cleaned-транскрипт:

    python tools/materialize_sections.py "<папка ролика>" --transcript --out "<папка ролика>/transcript.cleaned.md"

Название скрипта историческое. В обычном pipeline использовать его только с --transcript для очистки субтитров. Не запускать обычную материализацию смысловых разделов.

После успешной очистки удалить сырой SRT.

### Диагностика

- yt-dlp: command not found — пустой PATH; использовать явный путь выше.
- HTTP Error 429: Too Many Requests — подождать несколько минут и повторить.
- Sign in to confirm you're not a bot — добавить --cookies-from-browser chrome, предварительно закрыв Chrome.
- Предупреждение No supported JavaScript runtime обычно не мешает субтитрам.
- Скачивание через yt-dlp работает только в локальной среде, где есть программа и сетевой доступ. В облачной сессии не обходить это браузерным скачиванием субтитров.
- Если <lang>-orig отсутствует, посмотреть --list-subs и выбрать ручную дорожку оригинального языка.

Проверка доступа:

    "$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe/yt-dlp.exe" --simulate --print "%(title)s" "<ссылка>"

## Технический fallback: chunks

chunks/ не нужны для обычного обсуждения. Использовать их только если конкретная среда действительно не может нормально читать цельный transcript.cleaned.md.

    python tools/materialize_sections.py "<папка ролика>" --chunks

По умолчанию скрипт создаёт последовательные чанки примерно до 6000 символов и индекс chunks/README.md. Это техническая нарезка, не смысловая карта.

## Коммит и пуш

После каждой команды, которая изменила репозиторий, изменения сразу коммитить и пушить в main, без отдельного запроса разрешения.

Если один пользовательский запрос включает полный pipeline, по возможности сделать один итоговый коммит.

    git add -A
    git commit -m "<что сделано>"
    git push origin main

Если push отклонён из-за расхождения:

    git pull --rebase origin main
    git push origin main

## Прочее

- Язык в language — фактический язык оригинальной дорожки: например ru, uk, en.
- Video ID не использовать как имя папки.
- Не придумывать содержание ролика по названию, превью или старому вторичному описанию, когда доступен транскрипт.
