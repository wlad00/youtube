# AGENTS.md

Репозиторий с субтитрами YouTube-роликов и их структурой.

## Одна схема для всего репозитория

Один ролик — одна папка. Внутри только два вида файлов:

```text
<раздел>/<ГГГГ-ММ-ДД-slug-названия>/
  README.md                        — метаданные + структура ролика
  subtitles.<язык-оригинала>.srt   — появляется после команды «скачай субтитры»
```

Если известен только месяц публикации — `ГГГГ-ММ-slug-названия`.

Актуальный список разделов и их краткие описания ведутся в секции `## Разделы` файла `INDEX.md`. Новый автор — новая папка верхнего уровня со слагом «имя-фамилия» латиницей.

`INDEX.md` — единый каталог всех роликов, одна строка на ролик; в начале файла находится секция с описанием разделов.

Никаких других файлов в репозитории нет: ни отдельных файлов структуры, ни пустых заглушек субтитров, ни README с правилами внутри разделов. Правила живут только в этом файле.

## Три команды пользователя

Это три независимых шага. Ни один не запускает следующий сам — только по явной команде. Каждый шаг заканчивается коммитом и пушем в `main`.

Шаги 1 и 3 не требуют локальной машины: их можно сделать из любой сессии и даже прямой правкой файлов в веб-интерфейсе GitHub. Шаг 2 требует локальной машины с `yt-dlp`.

Поэтому в репозитории нет скриптов, генераторов и CI: всё делается обычной правкой файлов и работает из любого окружения. `INDEX.md` обновляется руками на том же шаге, где меняются файлы ролика.

Перед началом любого из трёх шагов в локальной сессии сначала выполнить `git pull --rebase origin main`. Правки могут прийти из другой сессии или прямо через веб-интерфейс GitHub, поэтому локальная копия `INDEX.md` и файлов роликов может быть устаревшей — ролик, который ищется по ссылке или названию, может уже существовать в `origin/main`, просто ещё не подтянут.

### 1. «Прими ролик: `<ссылка>`»

1. Получить метаданные страницы видео: название, каноническую ссылку, Video ID, дату публикации.
2. Создать папку `<раздел>/<ГГГГ-ММ-ДД-slug>/` и в ней `README.md` по шаблону ниже.
3. Добавить строку в `INDEX.md`: субтитры — «нет», структура — «нет», теги — `—`.
4. Закоммитить и запушить.

Запрещено на этом шаге: скачивать субтитры, искать транскрипт, запускать `yt-dlp` с любыми ключами субтитров, придумывать теги и содержание по названию.

### 2. «Скачай субтитры: `<ссылка>`»

1. Найти папку ролика (по `video_id` в `README.md` или по ссылке в `INDEX.md`).
2. Скачать командой ниже только оригинальную дорожку. Машинный перевод не качать никогда.
3. Сохранить как `subtitles.<язык-оригинала>.srt` в папке ролика; если yt-dlp отдал `subtitles.<язык>-orig.srt` — переименовать.
4. В `INDEX.md` в строке этого ролика поставить субтитры — «да».
5. Закоммитить и запушить: файл субтитров и `INDEX.md`.

### 3. «Сделай структуру: `<ссылка>`»

1. Прочитать `subtitles.*.srt` этого ролика. Без субтитров структуру не писать.
2. В `README.md` ниже front matter написать структуру: «Коротко» (2–4 предложения), затем нумерованные разделы с содержанием, и при пользе — факты и шаги.
3. В front matter поставить `structure_status: ready` и заполнить `tags` — только то, что подтверждено содержанием.
4. В `INDEX.md` в строке этого ролика поставить структуру — «да» и перенести `tags` в колонку тегов.
5. Закоммитить и запушить: `README.md` и `INDEX.md`.

## README.md ролика

Единственный файл метаданных и содержания. При регистрации:

```yaml
---
title: ""
youtube: ""
video_id: ""
date: ""
collection: ""
structure_status: pending
tags: []
---
```

Ниже front matter — заголовок ролика и одна строка-заглушка до появления структуры.

## INDEX.md

В начале файла находится секция `## Разделы` — актуальный список разделов с краткими описаниями. При добавлении или удалении раздела эту секцию необходимо обновить в том же коммите.

Одна строка на ролик, новые сверху (сортировка по дате, от новых к старым). Шаблон строки:

```text
| ГГГГ-ММ-ДД | [Название](раздел/папка/README.md) | [VIDEO_ID](https://www.youtube.com/watch?v=VIDEO_ID) | `раздел` | нет | нет | — |
```

Если ссылка на YouTube неизвестна — в колонке YouTube ставится `—`.

Источник истины — файлы, а не индекс:

- есть `subtitles.<язык>.srt` → субтитры «да», нет файла → «нет»;
- `structure_status: ready` → структура «да», `pending` → «нет».

Если индекс разошёлся с файлами — править индекс по файлам.

## Скачивание субтитров

`yt-dlp` установлен через winget, но его почти никогда нет в `PATH` сессии. Не проверять `yt-dlp --version`, а сразу запускать по явному пути из корня репозитория.

PowerShell:

```powershell
& "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe\yt-dlp.exe" --skip-download --write-auto-subs --write-subs --sub-langs "*-orig" --convert-subs srt --ffmpeg-location "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.FFmpeg_Microsoft.Winget.Source_8wekyb3d8bbwe\ffmpeg-N-125875-g5d4d3bdc61-win64-gpl\bin" -o "<папка ролика>/subtitles.%(ext)s" "<ссылка>"
```

Bash — тот же бинарник, но путь в POSIX-виде и без `&`:

```bash
"$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe/yt-dlp.exe" --skip-download --write-auto-subs --write-subs --sub-langs "*-orig" --convert-subs srt --ffmpeg-location "$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.FFmpeg_Microsoft.Winget.Source_8wekyb3d8bbwe/ffmpeg-N-125875-g5d4d3bdc61-win64-gpl/bin" -o "<папка ролика>/subtitles.%(ext)s" "<ссылка>"
```

`--ffmpeg-location` обязателен: без него `--convert-subs srt` падает с `ffmpeg not found`.

### Переименование после скачивания

Файл всегда приезжает как `subtitles.<язык>-orig.srt`. Это не ошибка команды: `*-orig` — код, которым YouTube обозначает оригинальную авто-дорожку (в отличие от `<язык>` без суффикса — машинного перевода), а yt-dlp вставляет код языка в имя файла сам, после шаблона `-o`. Отключить это опциями нельзя, поэтому переименование — обязательный второй шаг, а не ручная доводка.

PowerShell:

```powershell
Get-ChildItem "<папка ролика>\subtitles.*-orig.srt" | Rename-Item -NewName { $_.Name -replace '-orig\.srt$', '.srt' }
```

Bash:

```bash
for f in "<папка ролика>"/subtitles.*-orig.srt; do mv "$f" "${f%-orig.srt}.srt"; done
```

В папке ролика должен остаться ровно один файл субтитров — без суффикса `-orig`.

Проверка доступа тем же бинарником (печатает заголовок — значит сеть в порядке): `--simulate --print "%(title)s" "<ссылка>"`.

Если `*-orig` ничего не нашёл — у видео ручные субтитры: посмотреть `--list-subs` и взять дорожку оригинала без `-orig`.

### Диагностика: увидел → сделай

- `yt-dlp: command not found` — пустой `PATH`, а не «программы нет» и не блокировка сети. Запустить по явному пути выше.
- `HTTP Error 429: Too Many Requests` — лимит по IP, смена инструмента не поможет. Подождать несколько минут и повторить, не гнать запросы подряд.
- `Sign in to confirm you're not a bot` — добавить `--cookies-from-browser chrome`, предварительно закрыв Chrome. Для публичных видео куки не нужны.
- Предупреждение `No supported JavaScript runtime` на субтитры не влияет. Если станет ошибкой — deno установлен: `--js-runtimes "deno:$env:LOCALAPPDATA\Microsoft\WinGet\Packages\DenoLand.Deno_Microsoft.Winget.Source_8wekyb3d8bbwe\deno.exe"` (путь только в Windows-формате; проверено 2026-08-29).
- Скачивание работает только в локальной сессии на машине пользователя. В облачной сессии нет ни `yt-dlp`, ни файлов репозитория — сообщить пользователю, а не обходить.
- Не получать субтитры через браузер, WebFetch или веб-поиск: это упирается в прокси и создаёт ложный вывод «YouTube недоступен» (у `yt-dlp` прямой доступ есть, проверено 2026-08-29).

## Коммит и пуш

После каждой из трёх команд изменения сразу коммитятся и пушатся в `main` — отдельного разрешения спрашивать не нужно, это часть шага. Один шаг — один коммит.

```bash
git add -A
```

```bash
git commit -m "<что сделано>"
```

```bash
git push origin main
```

Если пуш отклонён из-за расхождения — сначала `git pull --rebase origin main`, затем повторить пуш.

## Прочее

- Язык в имени файла — всегда фактический язык оригинальной дорожки: `subtitles.ru.srt`, `subtitles.uk.srt`, `subtitles.en.srt`.
- Video ID не использовать как имя папки.
