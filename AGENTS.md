# AGENTS.md

Репозиторий с конспектами YouTube-видео и субтитрами к ним.

## Структура

```text
INDEX.md                     — общий поисковый каталог и статусы обработки
alexander-bolotnikov/
  lessons/                   — библейские уроки
  streams/                   — стримы
ivan-pendlishak/
  <файлы прямо в папке>
mvp/
  <ГГГГ-ММ-ДД-slug-названия>/
    README.md
    <ГГГГ-ММ-ДД-slug-названия>.pending.srt
    <ГГГГ-ММ-ДД-slug-названия>.<язык>.srt
    <ГГГГ-ММ-ДД-slug-названия>.structure.md
```

Папка автора — слаг «имя-фамилия» латиницей. Новый автор — новая папка верхнего уровня.

## Общий индекс и поиск

`INDEX.md` — единый поисковый каталог для всего репозитория: авторские коллекции, `mvp/` и будущие разделы. Одна строка — один ролик.

Минимальные поля строки: дата, видео, раздел, статус субтитров, статус структуры и поисковые метаданные.

### Источник истины для статусов

Статусы в `INDEX.md` не задаются произвольно, а определяются по файлам:

- есть `<base>.pending.srt` и нет настоящего `<base>.<язык>.srt` → **субтитры: не скачаны**;
- есть `<base>.<язык>.srt` → **субтитры: скачаны**;
- нет `<base>.structure.md` → **структура: не создана**;
- есть `<base>.structure.md` → **структура: создана**.

Файлы — источник истины. `INDEX.md` — удобное представление для поиска и контроля очереди. Если индекс расходится с файлами, привести индекс в соответствие с файлами.

### Когда обновлять INDEX.md

1. При добавлении новой ссылки/заготовки — сразу добавить строку в `INDEX.md`, даже если субтитры ещё не скачаны.
2. После скачивания субтитров — обновить статус субтитров.
3. После создания или изменения `*.structure.md` — обновить статус структуры и перенести в `INDEX.md` поисковые метаданные из этого файла.
4. Не придумывать теги, темы, инструменты и другие поисковые признаки на этапе добавления ссылки. Пока `*.structure.md` не создан, поле поисковых метаданных в индексе оставлять пустым/`—`.

## Файл структуры

Для обработанного ролика создаётся файл `<base>.structure.md` рядом с субтитрами. Для `mvp/` он лежит внутри папки ролика; в авторских коллекциях — рядом с `.srt`.

Структуру создавать только по содержимому субтитров, а не по одному названию или описанию ролика.

В начале `*.structure.md` хранить машинно-читаемые поисковые метаданные в YAML front matter. Использовать только реально применимые поля; ненужные оставлять пустыми:

```yaml
---
title: ""
youtube: ""
video_id: ""
date: ""
collection: ""
tags: []
topics: []
people: []
tools: []
projects: []
business_models: []
monetization: []
---
```

Дальше — содержательная структура ролика: краткое резюме, основные тезисы/разделы, факты, действия/шаги и другие полезные блоки по содержанию.

Именно `*.structure.md` является источником тегов, тем, инструментов, людей, проектов, бизнес-моделей, способов монетизации и других поисковых признаков для `INDEX.md`.

### MVP-заготовки

`mvp/` — отдельная тематическая коллекция роликов по быстрому заработку.

Когда пользователь присылает ссылку и просит добавить/оформить её в `mvp`:

1. Не скачивать субтитры без отдельной явной просьбы.
2. Определить название ролика и дату публикации на YouTube.
3. Создать папку по тому же принципу, что используется для имён файлов: `ГГГГ-ММ-ДД-slug-названия`. Если известен только месяц — `ГГГГ-ММ-slug-названия`.
4. **Не использовать Video ID как название папки.** Video ID хранить только в метаданных.
5. Внутри создать `README.md` с названием, канонической YouTube-ссылкой без tracking-параметров, Video ID и датой публикации. Статусы обработки хранить в `INDEX.md`, а не дублировать вручную в `README.md`.
6. Создать пустой файл `<имя-папки>.pending.srt` как место для будущих субтитров.
7. Сразу добавить ролик в `INDEX.md`: субтитры — «не скачаны», структура — «не создана», поисковые метаданные — `—`.
8. Когда пользователь позже явно попросит скачать субтитры, сохранить результат в этой же папке как `<имя-папки>.<язык>.srt`, удалить `.pending.srt` и обновить `INDEX.md`.
9. После создания `<имя-папки>.structure.md` обновить `INDEX.md` данными из его front matter.

## Именование файлов

`ГГГГ-ММ-ДД-slug.<ext>` — дата публикации видео на YouTube, slug из названия транслитом.
Если известен только месяц — `ГГГГ-ММ-slug` (как у `ivan-pendlishak`).

Конспект, структура и субтитры одного видео носят одинаковое базовое имя:

```text
2026-08-22-zakon-ili-duh.md
2026-08-22-zakon-ili-duh.structure.md
2026-08-22-zakon-ili-duh.ru.srt
```

## Скачивание субтитров

Когда пользователь пишет «скачай субтитры: `<ссылка>`» — без других уточнений:

1. Определить автора и дату публикации видео, выбрать папку и имя по правилам выше. Если ссылка уже оформлена в `mvp/`, использовать существующую папку и её базовое имя.
2. Скачать субтитры в `.srt` — **только через `yt-dlp`**, всегда дорожку оригинала: `--sub-langs "*-orig"`. Язык видео заранее знать не нужно, машинный перевод не качать никогда — для чтения агентом достаточно оригинала на любом языке.
3. Файл придёт как `<имя>.<язык>-orig.srt` — переименовать в `<имя>.<язык>.srt` (например `.uk-orig.srt` → `.uk.srt`). Если `*-orig` ничего не нашёл — у видео, скорее всего, ручные субтитры: посмотреть `--list-subs` и взять дорожку оригинала без `-orig`.
4. Если существовал `<имя>.pending.srt`, удалить его после успешного скачивания.
5. Обновить соответствующую строку `INDEX.md`: субтитры — «скачаны».
6. Не коммитить без явной просьбы.

### Готовая команда

`yt-dlp` установлен через winget, но его почти никогда нет в `PATH` сессии. Не проверять `yt-dlp --version`, а сразу запускать по явному пути из корня репозитория — работает и в PowerShell, и в Bash (в Bash путь вида `/c/Users/...`):

```powershell
& "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe\yt-dlp.exe" --skip-download --write-auto-subs --write-subs --sub-langs "*-orig" --convert-subs srt --ffmpeg-location "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.FFmpeg_Microsoft.Winget.Source_8wekyb3d8bbwe\ffmpeg-N-125875-g5d4d3bdc61-win64-gpl\bin" -o "<папка>/<имя>.%(ext)s" "<ссылка>"
```

`--ffmpeg-location` обязателен: без него `--convert-subs srt` падает с `ffmpeg not found`.

Проверка доступа тем же бинарником (печатает заголовок видео — значит сеть в порядке): `--simulate --print "%(title)s" "<ссылка>"`.

### Диагностика: увидел → сделай

- `yt-dlp: command not found` — это пустой `PATH`, а не «программы нет» и не блокировка сети. Запустить по явному пути выше.
- `HTTP Error 429: Too Many Requests` — лимит по IP, смена инструмента не поможет. Подождать несколько минут и повторить; не гнать запросы подряд — качать по одной языковой дорожке за запуск, `--list-subs` вызывать только при необходимости.
- `Sign in to confirm you're not a bot` — добавить `--cookies-from-browser chrome`, предварительно закрыв Chrome (иначе файл cookies заблокирован). Для публичных видео куки не нужны.
- Предупреждение `No supported JavaScript runtime` на субтитры не влияет. Если станет ошибкой — deno уже установлен, добавить `--js-runtimes "deno:$env:LOCALAPPDATA\Microsoft\WinGet\Packages\DenoLand.Deno_Microsoft.Winget.Source_8wekyb3d8bbwe\deno.exe"` (путь только в Windows-формате; проверено 2026-08-29).
- Скачивание работает только в локальной сессии на машине пользователя. В облачной сессии нет ни `yt-dlp`, ни файлов репозитория — сообщить пользователю, а не обходить.
- Не получать субтитры через браузер, WebFetch или веб-поиск: даже локально это упирается в прокси и создаёт ложный вывод «YouTube недоступен» (у `yt-dlp` прямой доступ есть, проверено 2026-08-29). Не писать конспект «по мотивам названия», не убедившись, что субтитров действительно не достать.

## Формат конспекта

`.md` с шапкой: заголовок, автор, тип, ссылка на YouTube, Video ID, дата публикации, дата обновления конспекта. Дальше — раздел об источнике, «Коротко», «Подробный конспект» с нумерованными разделами. Ориентироваться на существующие файлы.
