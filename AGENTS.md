# AGENTS.md

Репозиторий с конспектами YouTube-видео и субтитрами к ним.

## Структура

```text
INDEX.md                     — общий поисковый каталог и статусы обработки
alexander-bolotnikov/
  lessons/                   — библейские уроки
  streams/                   — стримы
ivan-pendlishak/
  <файлы прямо в папке>
mvp/
  <ГГГГ-ММ-ДД-slug-названия>/
    README.md
    subtitles.<язык-оригинала>.srt   # появляется только после явной команды скачать субтитры
```

Папка автора — слаг «имя-фамилия» латиницей. Новый автор — новая папка верхнего уровня.

## Два разных действия: регистрация и скачивание субтитров

**«Добавь / прими / оформи ролик» не означает «скачай субтитры».** Это разные операции и не должны запускать друг друга автоматически.

### Регистрация ролика

При регистрации новой ссылки нужно:

1. Получить доступные без субтитров метаданные источника: название, каноническую YouTube-ссылку, Video ID, дату публикации и, если доступно, канал/автора и другие базовые метаданные страницы видео.
2. Создать папку/метаданные по правилам соответствующей коллекции.
3. Сразу добавить ролик в `INDEX.md`, даже если дальнейшая обработка ещё не началась.
4. В индексе сохранить известные данные источника и поставить фактические статусы: **субтитры — не скачаны**, **структура — не создана**.
5. Не придумывать содержательные теги, темы, инструменты, бизнес-модели и другие признаки, требующие знания содержания ролика.

При регистрации **запрещено без отдельной явной просьбы пользователя**:

- скачивать субтитры;
- пытаться получить текст/транскрипт ролика;
- запускать `yt-dlp --write-subs`, `--write-auto-subs`, `--list-subs` или аналогичные действия с субтитрами;
- строить содержательную структуру по одному названию или описанию.

Получение обычных метаданных страницы видео для регистрации не считается скачиванием субтитров.

### Скачивание субтитров

Начинать работу с субтитрами только после отдельной явной команды пользователя вроде «скачай субтитры» или равнозначной ей. Тогда выполнять раздел «Скачивание субтитров» ниже.

## Общий индекс и поиск

`INDEX.md` — единый поисковый каталог для всего репозитория: авторские коллекции, `mvp/` и будущие разделы. Одна строка — один ролик.

Минимальные поля строки: дата, видео, источник, Video ID, раздел, статус субтитров, статус структуры и поисковые метаданные. Канал/автора и другие базовые метаданные можно добавлять, когда они доступны.

### Источник истины для статусов

Для `mvp/`:

- нет `subtitles.<язык>.srt` → **субтитры: не скачаны**;
- есть `subtitles.<язык>.srt` → **субтитры: скачаны**;
- в `README.md` стоит `structure_status: pending` → **структура: не создана**;
- в `README.md` стоит `structure_status: ready` → **структура: создана**.

Для авторских коллекций, где файлы одного ролика лежат в общей папке:

- наличие `<base>.<язык>.srt` означает, что субтитры скачаны;
- наличие `<base>.structure.md` означает, что структура создана.

Файлы ролика — источник истины. `INDEX.md` — удобное представление для поиска и контроля очереди. Если индекс расходится с файлами, привести индекс в соответствие с ними.

### Когда обновлять INDEX.md

1. При регистрации новой ссылки — сразу добавить строку в `INDEX.md`, даже если субтитры ещё не скачаны.
2. Уже на этом этапе заполнить доступные метаданные источника: название, дата, каноническая ссылка, Video ID, раздел и другие достоверно полученные базовые данные.
3. После скачивания субтитров — обновить статус субтитров.
4. После создания или изменения структуры — обновить статус структуры и поисковые метаданные.
5. Не придумывать теги, темы, инструменты и другие поисковые признаки на этапе регистрации. Пока структура не создана, поле поисковых метаданных в индексе оставлять `—`.

## Структура и поисковые метаданные

Структуру создавать только по содержимому субтитров, а не по одному названию или описанию ролика.

### Для `mvp/`

Отдельный `structure.md` **не создаётся**. `README.md` ролика — единый файл метаданных и структуры.

При регистрации `README.md` содержит YAML front matter с базовыми данными и `structure_status: pending`:

```yaml
---
title: ""
youtube: ""
video_id: ""
date: ""
collection: "mvp"
channel: ""
structure_status: pending
tags: []
topics: []
people: []
tools: []
projects: []
business_models: []
monetization: []
---
```

После обработки субтитров:

1. изменить `structure_status` на `ready`;
2. заполнить только подтверждённые содержанием поисковые поля;
3. ниже front matter дописать краткое резюме, основные тезисы/разделы, факты, действия/шаги и другие полезные блоки;
4. перенести поисковые данные из `README.md` в соответствующую строку `INDEX.md`.

Таким образом, для одного MVP-ролика не нужны одновременно `README.md` и `structure.md`: всю структурированную информацию хранит `README.md`.

### Для авторских коллекций

Поскольку несколько роликов лежат рядом в одной папке, структура при необходимости хранится отдельно как `<base>.structure.md`, рядом с `<base>.<язык>.srt`.

## MVP-заготовки

`mvp/` — отдельная тематическая коллекция роликов по быстрому заработку.

Когда пользователь присылает ссылку и просит добавить/оформить её в `mvp`:

1. Выполнить только **регистрацию ролика**. Не скачивать и не искать субтитры без отдельной явной просьбы.
2. Определить название ролика и дату публикации на YouTube, а также доступные базовые метаданные источника.
3. Создать папку `ГГГГ-ММ-ДД-slug-названия`. Если известен только месяц — `ГГГГ-ММ-slug-названия`.
4. **Не использовать Video ID как название папки.** Video ID хранить в метаданных.
5. Создать внутри только `README.md` с YAML front matter по шаблону выше. При регистрации `structure_status: pending`, поисковые массивы пустые.
6. **Не создавать пустой `.pending.srt`.** Отсутствие `subtitles.<язык>.srt` уже означает, что субтитры не скачаны.
7. Сразу добавить ролик в `INDEX.md`: источник и базовые метаданные — заполнить; субтитры — «не скачаны»; структура — «не создана»; поисковые метаданные — `—`.
8. Когда пользователь позже явно попросит скачать субтитры, сохранить оригинальную дорожку в этой же папке как `subtitles.<язык-оригинала>.srt` и обновить `INDEX.md`.
9. Когда пользователь попросит создать структуру/обработать ролик, читать сохранённые субтитры, дополнить `README.md`, поставить `structure_status: ready` и обновить `INDEX.md`.

## Именование файлов

В авторских коллекциях используется существующая схема:

`ГГГГ-ММ-ДД-slug.<ext>` — дата публикации видео на YouTube, slug из названия транслитом. Если известен только месяц — `ГГГГ-ММ-slug`.

Пример:

```text
2026-08-22-zakon-ili-duh.structure.md
2026-08-22-zakon-ili-duh.ru.srt
```

Здесь `.ru.srt` означает, что **оригинальная дорожка этого конкретного видео русская**. Это не требование всегда скачивать русский язык.

В `mvp/` длинное имя уже находится в названии папки, поэтому внутри используются короткие стабильные имена:

```text
README.md
subtitles.en.srt
```

Если оригинальный язык русский — `subtitles.ru.srt`; украинский — `subtitles.uk.srt`; английский — `subtitles.en.srt`; и т. д. Код языка всегда соответствует **оригинальной дорожке**, а не выбранному языку перевода.

## Скачивание субтитров

Когда пользователь пишет «скачай субтитры: `<ссылка>`» — без других уточнений:

1. Определить папку ролика по правилам выше. Если ссылка уже зарегистрирована в `mvp/`, использовать существующую папку.
2. Скачать субтитры в `.srt` — **только через `yt-dlp` и только оригинальную дорожку**: `--sub-langs "*-orig"`. Машинный перевод не качать никогда.
3. Если `*-orig` ничего не нашёл — у видео, скорее всего, ручные субтитры: посмотреть `--list-subs` только в рамках явной команды на скачивание и взять дорожку оригинала без `-orig`.
4. Для авторских коллекций файл, пришедший как `<имя>.<язык>-orig.srt`, переименовать в `<имя>.<язык>.srt`.
5. Для `mvp/` файл сохранить/переименовать в `subtitles.<язык>.srt`, где `<язык>` — фактический оригинальный язык ролика.
6. Обновить соответствующую строку `INDEX.md`: субтитры — «скачаны».
7. Не коммитить без явной просьбы.

### Готовая команда

`yt-dlp` установлен через winget, но его почти никогда нет в `PATH` сессии. Не проверять `yt-dlp --version`, а сразу запускать по явному пути из корня репозитория — работает и в PowerShell, и в Bash (в Bash путь вида `/c/Users/...`):

```powershell
& "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe\yt-dlp.exe" --skip-download --write-auto-subs --write-subs --sub-langs "*-orig" --convert-subs srt --ffmpeg-location "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.FFmpeg_Microsoft.Winget.Source_8wekyb3d8bbwe\ffmpeg-N-125875-g5d4d3bdc61-win64-gpl\bin" -o "<папка>/<имя>.%(ext)s" "<ссылка>"
```

Для `mvp/` в `<имя>` использовать `subtitles`.

`--ffmpeg-location` обязателен: без него `--convert-subs srt` падает с `ffmpeg not found`.

Проверка доступа тем же бинарником (печатает заголовок видео — значит сеть в порядке): `--simulate --print "%(title)s" "<ссылка>"`.

### Диагностика: увидел → сделай

- `yt-dlp: command not found` — это пустой `PATH`, а не «программы нет» и не блокировка сети. Запустить по явному пути выше.
- `HTTP Error 429: Too Many Requests` — лимит по IP, смена инструмента не поможет. Подождать несколько минут и повторить; не гнать запросы подряд — качать по одной языковой дорожке за запуск, `--list-subs` вызывать только при необходимости.
- `Sign in to confirm you're not a bot` — добавить `--cookies-from-browser chrome`, предварительно закрыв Chrome (иначе файл cookies заблокирован). Для публичных видео куки не нужны.
- Предупреждение `No supported JavaScript runtime` на субтитры не влияет. Если станет ошибкой — deno уже установлен, добавить `--js-runtimes "deno:$env:LOCALAPPDATA\Microsoft\WinGet\Packages\DenoLand.Deno_Microsoft.Winget.Source_8wekyb3d8bbwe\deno.exe"` (путь только в Windows-формате; проверено 2026-08-29).
- Скачивание работает только в локальной сессии на машине пользователя. В облачной сессии нет ни `yt-dlp`, ни файлов репозитория — сообщить пользователю, а не обходить.
- Не получать субтитры через браузер, WebFetch или веб-поиск: даже локально это упирается в прокси и создаёт ложный вывод «YouTube недоступен» (у `yt-dlp` прямой доступ есть, проверено 2026-08-29). Не писать конспект «по мотивам названия», не убедившись, что субтитров действительно не достать.

## Формат конспекта

`.md` с шапкой: заголовок, автор, тип, ссылка на YouTube, Video ID, дата публикации, дата обновления конспекта. Дальше — раздел об источнике, «Коротко», «Подробный конспект» с нумерованными разделами. Ориентироваться на существующие файлы.
