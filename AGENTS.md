# AGENTS.md

Репозиторий с субтитрами YouTube-роликов, их структурой и смысловыми разделами для последующей проработки.

## Одна схема для всего репозитория

Один ролик — одна папка. Базовые файлы и производные разделы:

```text
<раздел[/подраздел...]>/<ГГГГ-ММ-ДД-slug-названия>/
  README.md                        — метаданные + человекочитаемая карта смысловых разделов
  subtitles.<язык-оригинала>.srt   — сырой исходник; сохраняется после скачивания
  transcript.cleaned.md            — единая очищенная расшифровка с таймкодами
  sections.yaml                    — финальная машиночитаемая карта разделов после полного прохода
  chunks/                           — опциональный fallback: техническая нарезка очищенной расшифровки
    README.md                       — индекс размеров, интервалов и ссылок
    01.md                           — первый ограниченный по размеру чанк
    02.md                           — следующий чанк
  sections/                         — материализованные смысловые разделы
    01.md                          — полный текст первого смыслового раздела
    02.md                          — полный текст второго смыслового раздела
    ...
```

Если известен только месяц публикации — `ГГГГ-ММ-slug-названия`.

`subtitles.*.srt` сохраняется как сырой исходник и не удаляется после очистки. `transcript.cleaned.md` — обязательная рабочая цельная версия без повторов rolling captions и основной вход для смысловой нарезки. `chunks/` — только опциональный fallback для последовательного чтения; при обычной подготовке ролика они не создаются.

`README.md` хранит человекочитаемую карту уже подтверждённых смысловых разделов и может быть частичной: непрочитанный остаток не размечать, а незавершённый последний раздел явно помечать как предварительный. После полного прохода по ролику создаётся финальная машиночитаемая карта `sections.yaml`. Для команд «Нарежь разделы» / «Создай разделы» файлы `sections/*.md` считаются generated-only и создаются скриптом. Явное исключение — прогрессивная ручная команда «Создай карту» / «Создай раздел» / «Создай первый раздел», где исполнитель сам создаёт эти файлы по `WORKFLOWS/create-map.md`.

`sections.yaml` — каноническая машиночитаемая карта смысловых границ для новой команды «Нарежь разделы». `tools/materialize_sections.py` читает её, валидирует непрерывность и создаёт `sections/*.md` с той же дедупликацией rolling captions, что используется для `transcript.cleaned.md`. Для старых роликов без `sections.yaml` скрипт сохраняет совместимость с картой в `README.md`.

Актуальный список разделов и их краткие описания ведутся в секции `## Разделы` файла `INDEX.md`. Авторские коллекции могут быть самостоятельным разделом либо вложенным подразделом тематической коллекции; религиозные/субботние авторские коллекции живут внутри `bible/`.

`INDEX.md` — единый каталог всех роликов, одна строка на ролик; в начале файла находится секция с описанием разделов.

Базовые правила репозитория живут в этом файле. Подробные специализированные процессы можно выносить в `WORKFLOWS/*.md`; если на такой файл есть явная ссылка из `AGENTS.md`, он является обязательным продолжением инструкции для соответствующей команды. Для материализации смысловых разделов по командам «Нарежь разделы» / «Создай разделы» разрешён репозиторный скрипт `tools/materialize_sections.py`; он не определяет смысловые границы, а только создаёт файлы по уже принятой агентом карте.

## Основные команды пользователя

Основной pipeline состоит из трёх шагов. Каждый шаг запускается только по явной команде и, если в нём были изменения, заканчивается коммитом и пушем в `main`.

Шаг 1 не требует локальной машины. Шаг 2 требует локальной машины с `yt-dlp`. В шаге 3 смысловую карту можно подготовить в любой сессии, но физическая материализация `sections/*.md` требует локальной машины с Python.

Перед началом любого шага в локальной сессии сначала выполнить `git pull --rebase origin main`. Правки могут прийти из другой сессии или через GitHub, поэтому локальная копия может быть устаревшей.

Если пользователь присылает голую ссылку на видео без слов команды, это выполняется как шаг 1 и сразу шаг 2 одним заходом: приём ролика и скачивание субтитров. Раздел для нового ролика подбирается автоматически по содержанию; при неоднозначности — `unsorted/`.

### 1. «Прими ролик: `<ссылка>`» (ссылку можно заменить любыми признаками)

0. Если ссылки нет — найти ролик по тому, что известно: название, канал, автор, тема, примерная дата, фраза из ролика, снимок экрана. Искать поиском YouTube через `yt-dlp`, обычный веб-поиск свежие ролики не индексирует:

   ```bash
   "$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe/yt-dlp.exe" --simulate --print "%(title)s | %(channel)s | %(upload_date)s | %(id)s" "ytsearch10:<запрос>"
   ```

   Если совпадение одно и однозначное — брать его и работать дальше без вопроса. Если кандидатов несколько — показать их списком (название, канал, дата, ID) и дать пользователю выбрать; при нуле совпадений — менять запрос.
1. Получить метаданные страницы видео: название, каноническую ссылку, Video ID, дату публикации.
2. Создать папку `<раздел>/<ГГГГ-ММ-ДД-slug>/` и в ней `README.md`. Если раздел неоднозначен — `unsorted/`, не спрашивая пользователя.
3. Добавить строку в `INDEX.md`: субтитры — «нет», структура — «нет», теги — `—`.
4. Закоммитить и запушить.

На этом шаге не скачивать субтитры и не придумывать содержание по названию.

### 2. «Скачай субтитры: `<ссылка>`»

1. Найти папку ролика по `video_id` или ссылке.
2. Скачать только оригинальную дорожку. Машинный перевод не качать.
3. Сохранить сырой источник как `subtitles.<язык-оригинала>.srt`; если получен суффикс `-orig`, переименовать. Сырой SRT не удалять.
4. **Обязательно** создать один постоянный очищенный файл:

   ```bash
   python tools/materialize_sections.py "<папка ролика>" --transcript --out "<папка ролика>/transcript.cleaned.md"
   ```

   `transcript.cleaned.md` дедуплицирует rolling captions, сохраняет таймкоды и является основным файлом для последующей смысловой нарезки.
5. По умолчанию **не создавать `chunks/`**. Они остаются опциональным fallback.
6. В `INDEX.md` поставить субтитры — «да».
7. Закоммитить и запушить сырой SRT, `transcript.cleaned.md` и `INDEX.md`.

### 3. «Нарежь разделы: `<ссылка или признаки ролика>`»

Цель — быстро подготовить ролик к содержательному обсуждению, не делая заранее подробный конспект.

1. Найти папку ролика. Основной вход — `transcript.cleaned.md`. Если его нет, но есть `subtitles.*.srt`, сначала создать `transcript.cleaned.md` командой `--transcript`. Без исходных субтитров разделы не создавать.
2. Прочитать **весь `transcript.cleaned.md`** последовательно один раз.
3. Определить смысловые границы по смене законченной мысли/аргумента, а не по техническому размеру. Предпочитать минимальное число достаточно крупных самостоятельно обсуждаемых разделов. Ориентир 5–10 минут мягкий; цельность мысли важнее.
4. Создать или заменить `sections.yaml`. Модель записывает **только границы и короткие содержательные названия** — без `Сути`, `Опорных мыслей`, вопросов и тегов.

   ```yaml
   sections:
     - title: "Введение и постановка проблемы"
       start: "00:00:00"
       end: "00:07:40"
     - title: "Основной аргумент"
       start: "00:07:40"
       end: "00:18:15"
     - title: "Выводы и последствия"
       start: "00:18:15"
       end: END
   ```

   Первый раздел начинается с `00:00:00`, конец каждого равен началу следующего, последний заканчивается `END`.
5. На локальной машине сразу запустить:

   ```bash
   python tools/materialize_sections.py "<папка ролика>"
   ```

   Скрипт читает `sections.yaml`, проверяет границы, синхронизирует минимальную карту `## Разделы` в `README.md` и создаёт `sections/NN.md`. Текст разделов очищен от повторов rolling captions тем же алгоритмом, что и `transcript.cleaned.md`.
6. Закоммитить и запушить `sections.yaml`, обновлённый `README.md` и `sections/*.md`. Если `transcript.cleaned.md` пришлось создать на этом шаге, включить и его.
7. Команда не меняет `structure_status`, `tags` или `review`.

Если локальной машины нет, допустимо завершить только интеллектуальную часть: записать и закоммитить `sections.yaml`, явно сообщив, что `sections/*.md` ещё не материализованы.

Фраза **«Создай разделы»** для совместимости означает то же самое, что **«Нарежь разделы»**. Старый тяжёлый режим с обязательными `Суть`, `Опорные мысли`, `Для обсуждения` и `Темы` больше не является default.

### «Создай карту» / «Создай раздел» / «Создай первый раздел»

Все три формулировки **полностью эквивалентны** и запускают один прогрессивный ручной процесс **без скрипта материализации**. Его приоритет — как можно быстрее подготовить первый законченный смысловой раздел для параллельного обсуждения: раздел 1 создаётся, коммитится и пушится сразу после определения первой надёжной границы, пользователь получает сообщение, что он готов, а обработка остальных разделов продолжается без новой команды.

Это **не** синоним команды «Создай разделы»: форма во множественном числе остаётся скриптовым процессом из шага 3 выше.

Полный обязательный протокол: [`WORKFLOWS/create-map.md`](WORKFLOWS/create-map.md).

### Дополнительно: «Сделай структуру: `<ссылка>`»

Это отдельный необязательный аналитический шаг, только по явной команде. Он не нужен для создания `sections/`.

1. Прочитать `transcript.cleaned.md` (если его нет — создать из SRT).
2. В `README.md` написать «Коротко» (2–4 предложения), затем нумерованную структуру содержания и, если полезно, факты/шаги.
3. Поставить `structure_status: ready` и заполнить `tags` только по подтверждённому содержанию.
4. Обновить строку `INDEX.md`.
5. Закоммитить и запушить `README.md` и `INDEX.md`.

### Обсуждение без предварительной нарезки

`chunks/` остаются fallback для случая, когда владелец хочет начать обсуждение неподготовленного ролика немедленно. Их технические границы не считать смысловыми. Определившиеся по ходу разговора устойчивые границы можно затем перенести в `sections.yaml` и материализовать обычной командой «Нарежь разделы».

## README.md ролика

Единственный файл метаданных и авторской карты содержания. При регистрации:

```yaml
---
title: ""
youtube: ""
video_id: ""
date: ""
collection: ""
structure_status: pending
tags: []
---
```

Ниже front matter — заголовок ролика и одна строка-заглушка до появления структуры или разделов.

### `review` — состояние кураторской проработки

В front matter `README.md` может присутствовать отдельный блок `review`, который ведёт **Куратор ATLAS** при содержательной проработке ролика. Это допустимая часть metadata ролика, а не данные YouTube ingestion/structure pipeline.

Канонический способ заполнения и смысл значений определён в `wlad00/ATLAS` → `ALGORITHMS/youtube-video-review.md`. Здесь фиксируется только граница ответственности.

Форма блока:

```yaml
review:
  stage: discussed
  state: open
  sessions:
    - date: "2026-09-12"
      turns: 12
      minutes: 35
      insights: 3
```

Правила для агентов этого репозитория:

- отсутствие `review` допустимо и означает, что Куратор ещё не начал вести review-метаданные этого ролика;
- команды «прими ролик», «скачай субтитры», «сделай структуру», «создай разделы» и «создай карту» **не создают и не изменяют** `review`;
- если `review` уже существует, при любых обычных правках ролика сохранить его без изменений;
- не удалять, не переименовывать и не нормализовать поля `review.stage`, `review.state`, `review.sessions` как «неизвестные» metadata;
- review-история конкретного ролика канонически хранится здесь, в его `README.md`; ATLAS хранит алгоритм работы и собственные durable выводы, но не дублирует эту статистику.

## INDEX.md

В начале файла находится секция `## Разделы` — актуальный список разделов с краткими описаниями. При добавлении или удалении раздела эту секцию необходимо обновить в том же коммите.

Одна строка на ролик, новые сверху (сортировка по дате, от новых к старым). Шаблон строки:

```text
| ГГГГ-ММ-ДД | [Название](раздел/папка/README.md) | [VIDEO_ID](https://www.youtube.com/watch?v=VIDEO_ID) | `раздел` | нет | нет | — |
```

Если ссылка на YouTube неизвестна — в колонке YouTube ставится `—`.

Источник истины — файлы, а не индекс:

- есть `subtitles.<язык>.srt` → субтитры «да», нет файла → «нет»;
- `structure_status: ready` → структура «да», `pending` → «нет».

Наличие `sections/` в `INDEX.md` пока отдельно не отражается.

Если индекс разошёлся с файлами — править индекс по файлам.

## Неотсортированные ролики

`unsorted/` — раздел для роликов, у которых подходящий раздел неочевиден. Правило простое: сомнение в разделе не повод останавливать работу и спрашивать пользователя. Кладём в `unsorted/` и продолжаем — скачиваем субтитры, делаем структуру или создаём разделы. Разобрать раздел всегда можно потом, а прерванная на вопросе команда стоит пользователю времени.

Перенос из `unsorted/` в настоящий раздел — отдельная команда пользователя: переместить папку и поправить строку в `INDEX.md` (путь и колонку раздела) одним коммитом.

После любой основной команды, если в `unsorted/` есть хотя бы один ролик, в конце ответа одной строкой напомнить: сколько роликов ждёт разбора и что их можно разложить по разделам.

## Скачивание субтитров

`yt-dlp` установлен через winget, но его почти никогда нет в `PATH` сессии. Не проверять `yt-dlp --version`, а сразу запускать по явному пути из корня репозитория.

Маска `--sub-langs "*-orig"` в версии yt-dlp 2026.07.04 сломана — падает с `Wrong regex for subtitlelangs: *-orig` (проверено 2026-09-09). Поэтому сначала узнать код языка оригинала, потом подставить его явно вместо маски:

```powershell
& "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe\yt-dlp.exe" --list-subs "<ссылка>"
```

В выводе найти строку вида `ru-orig  Russian (Original)` — это и есть код языка (`<lang>-orig`) для команды ниже.

PowerShell:

```powershell
& "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe\yt-dlp.exe" --skip-download --write-auto-subs --write-subs --sub-langs "<lang>-orig" --convert-subs srt --no-progress --ffmpeg-location "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.FFmpeg_Microsoft.Winget.Source_8wekyb3d8bbwe\ffmpeg-N-125875-g5d4d3bdc61-win64-gpl\bin" -o "<папка ролика>/subtitles.%(ext)s" "<ссылка>"
```

Bash — тот же бинарник, но путь в POSIX-виде и без `&`:

```bash
"$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe/yt-dlp.exe" --skip-download --write-auto-subs --write-subs --sub-langs "<lang>-orig" --convert-subs srt --no-progress --ffmpeg-location "$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.FFmpeg_Microsoft.Winget.Source_8wekyb3d8bbwe/ffmpeg-N-125875-g5d4d3bdc61-win64-gpl/bin" -o "<папка ролика>/subtitles.%(ext)s" "<ссылка>"
```

`--ffmpeg-location` обязателен: без него `--convert-subs srt` падает с `ffmpeg not found`.

`--no-progress` убирает полосу загрузки: вместо десятка строк с процентами и скоростью остаётся одна строка о завершении. На одном ролике это мелочь, на пачке из десятка — заметная доля вывода, поэтому ключ не убирать.

Если маску всё же попробовать по старой памяти и она снова заработает в новой версии yt-dlp — можно вернуться к `"*-orig"` и убрать шаг с `--list-subs`; до тех пор явный код языка надёжнее.

### Переименование после скачивания

Файл всегда приезжает как `subtitles.<язык>-orig.srt`. Это не ошибка команды: `*-orig` — код, которым YouTube обозначает оригинальную авто-дорожку (в отличие от `<язык>` без суффикса — машинного перевода), а yt-dlp вставляет код языка в имя файла сам, после шаблона `-o`. Отключить это опциями нельзя, поэтому переименование — обязательный второй шаг, а не ручная доводка.

PowerShell:

```powershell
Get-ChildItem "<папка ролика>\subtitles.*-orig.srt" | Rename-Item -NewName { $_.Name -replace '-orig\.srt$', '.srt' }
```

Bash:

```bash
for f in "<папка ролика>"/subtitles.*-orig.srt; do mv "$f" "${f%-orig.srt}.srt"; done
```

В папке ролика должен остаться ровно один файл субтитров — без суффикса `-orig`.

Сразу после переименования создать автоматические чанки:

```powershell
python tools/materialize_sections.py "<папка ролика>" --chunks
```

Для уже существующего `subtitles.<язык>.srt` используется та же команда: повторно скачивать
исходник не требуется.

Проверка доступа тем же бинарником (печатает заголовок — значит сеть в порядке): `--simulate --print "%(title)s" "<ссылка>"`.

Если `*-orig` ничего не нашёл — у видео ручные субтитры: посмотреть `--list-subs` и взять дорожку оригинала без `-orig`.

### Диагностика: увидел → сделай

- `yt-dlp: command not found` — пустой `PATH`, а не «программы нет» и не блокировка сети. Запустить по явному пути выше.
- `HTTP Error 429: Too Many Requests` — лимит по IP, смена инструмента не поможет. Подождать несколько минут и повторить, не гнать запросы подряд.
- `Sign in to confirm you're not a bot` — добавить `--cookies-from-browser chrome`, предварительно закрыв Chrome. Для публичных видео куки не нужны.
- Предупреждение `No supported JavaScript runtime` на субтитры не влияет. Если станет ошибкой — deno установлен: `--js-runtimes "deno:$env:LOCALAPPDATA\Microsoft\WinGet\Packages\DenoLand.Deno_Microsoft.Winget.Source_8wekyb3d8bbwe\deno.exe"` (путь только в Windows-формате; проверено 2026-08-29).
- Скачивание работает только в локальной сессии на машине пользователя. В облачной сессии нет ни `yt-dlp`, ни файлов репозитория — сообщить пользователю, а не обходить.
- Не получать субтитры через браузер, WebFetch или веб-поиск: это упирается в прокси и создаёт ложный вывод «YouTube недоступен» (у `yt-dlp` прямой доступ есть, проверено 2026-08-29).

## Материализация смысловых разделов

`tools/materialize_sections.py` работает только с локальной копией репозитория и использует только стандартную библиотеку Python.

Запуск из корня репозитория:

```bash
python tools/materialize_sections.py "<папка ролика>"
```

Скрипт:

- находит ровно один `subtitles.*.srt`;
- если есть `sections.yaml`, использует его как основную карту; для старых роликов без YAML умеет читать legacy-блок `<!-- sections:begin --> ... <!-- sections:end -->` из `README.md`;
- проверяет начало с `00:00:00`, непрерывность границ и `END` только у последнего раздела;
- для YAML-карты автоматически синхронизирует минимальный блок `## Разделы` в `README.md`;
- дедуплицирует rolling captions тем же алгоритмом, что `--transcript`, и материализует очищенный текст по смысловым интервалам;
- пересоздаёт только сгенерированные `sections/NN.md`.

`sections/` считается generated-only для скриптового процесса «Нарежь разделы» / «Создай разделы». Команда «Создай карту» — единственное явное исключение: она создаёт `sections/NN.md` вручную по `transcript.cleaned.md`. Собственные заметки и durable выводы в `sections/` всё равно не помещать — они живут в `README.md` ролика.

## Автоматические чанки очищенной расшифровки

`--chunks` — опциональный fallback для последовательного чтения неподготовленного ролика. Команда «Скачай субтитры» его по умолчанию не запускает. Режим не требует смысловой карты и не меняет `README.md`, `sections/` или `review`. Сырой `subtitles.*.srt` остаётся архивным источником, а `transcript.cleaned.md` — основной рабочей копией для чтения.

```bash
python tools/materialize_sections.py "<папка ролика>" --chunks
```

Скрипт дедуплицирует повторы rolling captions тем же способом, что `--transcript`, и
полностью раскладывает очищенный текст по последовательным `chunks/NN.md`. По умолчанию
текст каждого чанка ограничен 6000 символами. `chunks/README.md` содержит число чанков,
их размеры, непрерывные интервалы и ссылки для чтения через GitHub. Повторный запуск на
том же SRT создаёт те же файлы; `chunks/` считается generated-only.

### Очищенная расшифровка для чтения

Тот же скрипт с ключом `--transcript` ничего не создаёт в репозитории, а выдаёт расшифровку ролика для чтения: повторы «ползущих» субтитров YouTube склеены, метки времени сохранены. Нужен на шаге «нарежь разделы», чтобы размечать границы, не загружая сырой SRT.

```bash
python tools/materialize_sections.py "<папка ролика>" --transcript --out "<временный файл вне репозитория>"
```

- `--out` лучше указывать всегда: в Windows-консоли кириллица в stdout портится;
- после скачивания субтитров стандартный `--out` — `<папка ролика>/transcript.cleaned.md`; файл коммитится и служит цельной рабочей копией для чтения;
- сырой SRT остаётся первичным архивным источником и не удаляется;
- `--window` задаёт, сколько секунд текста идёт под одной меткой времени (по умолчанию 30);
- `chunks/` и `transcript.cleaned.md` должны представлять один и тот же очищенный текст; смысловые границы поверх них задаются отдельно.

## Коммит и пуш

После каждой основной команды изменения сразу коммитятся и пушатся в `main` — отдельного разрешения спрашивать не нужно, это часть шага. Один пользовательский шаг — один итоговый коммит, если технически возможно. Исключение — «Создай карту» / «Создай раздел» / «Создай первый раздел»: ради минимального времени до начала обсуждения первый законченный раздел намеренно получает отдельный ранний commit+push, а завершение всей карты — финальный commit+push.

```bash
git add -A
```

```bash
git commit -m "<что сделано>"
```

```bash
git push origin main
```

Если пуш отклонён из-за расхождения — сначала `git pull --rebase origin main`, затем повторить пуш.
