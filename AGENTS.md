# AGENTS.md

Репозиторий с субтитрами YouTube-роликов, их структурой и смысловыми разделами для последующей проработки.

## Одна схема для всего репозитория

Один ролик — одна папка. Базовые файлы и производные разделы:

```text
<раздел[/подраздел...]>/<ГГГГ-ММ-ДД-slug-названия>/
  README.md                        — метаданные + структура + карта смысловых разделов
  subtitles.<язык-оригинала>.srt   — появляется после команды «скачай субтитры»
  sections/                        — появляется после команды «создай разделы»
    01.md                          — полный текст первого смыслового раздела
    02.md                          — полный текст второго смыслового раздела
    ...
```

Если известен только месяц публикации — `ГГГГ-ММ-slug-названия`.

`sections/*.md` — производные файлы для быстрого чтения и обсуждения отдельного законченного фрагмента ролика. Они генерируются из исходного `subtitles.*.srt` по смысловым границам, которые агент заранее фиксирует в `README.md`. Вручную содержимое `sections/*.md` не редактировать: при изменении границ или описаний их нужно пересоздать скриптом.

Актуальный список разделов и их краткие описания ведутся в секции `## Разделы` файла `INDEX.md`. Авторские коллекции могут быть самостоятельным разделом либо вложенным подразделом тематической коллекции; религиозные/субботние авторские коллекции живут внутри `bible/`.

`INDEX.md` — единый каталог всех роликов, одна строка на ролик; в начале файла находится секция с описанием разделов.

Правила живут только в этом файле. Для материализации смысловых разделов разрешён репозиторный скрипт `tools/materialize_sections.py`; он не определяет смысловые границы, а только создаёт файлы по уже принятой агентом карте.

## Четыре команды пользователя

Это четыре независимых шага. Ни один не запускает следующий сам — только по явной команде. Каждый шаг заканчивается коммитом и пушем в `main`.

Шаги 1 и 3 не требуют локальной машины. В шаге 4 смысловую карту тоже можно подготовить из любой сессии, но физическое создание `sections/*.md` требует локальной машины с Python. Шаг 2 требует локальной машины с `yt-dlp`.

Перед началом любого из четырёх шагов в локальной сессии сначала выполнить `git pull --rebase origin main`. Правки могут прийти из другой сессии или прямо через веб-интерфейс GitHub, поэтому локальная копия `INDEX.md` и файлов роликов может быть устаревшей — ролик, который ищется по ссылке или названию, может уже существовать в `origin/main`, просто ещё не подтянут.

### 1. «Прими ролик: `<ссылка>`» (ссылку можно заменить любыми признаками)

0. Если ссылки нет — найти ролик по тому, что известно: название, канал, автор, тема, примерная дата, фраза из ролика, снимок экрана. Искать поиском YouTube через `yt-dlp`, обычный веб-поиск свежие ролики не индексирует:

   ```bash
   "$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe/yt-dlp.exe" --simulate --print "%(title)s | %(channel)s | %(upload_date)s | %(id)s" "ytsearch10:<запрос>"
   ```

   Если совпадение одно и однозначное — брать его и работать дальше без вопроса. Если кандидатов несколько — показать их списком (название, канал, дата, ID) и дать пользователю выбрать; при нуле совпадений — менять запрос, а не сдаваться после первой попытки.
1. Получить метаданные страницы видео: название, каноническую ссылку, Video ID, дату публикации.
2. Создать папку `<раздел>/<ГГГГ-ММ-ДД-slug>/` и в ней `README.md` по шаблону ниже. Если раздел неоднозначен — `unsorted/`, не спрашивая пользователя (см. «Неотсортированные ролики»).
3. Добавить строку в `INDEX.md`: субтитры — «нет», структура — «нет», теги — `—`.
4. Закоммитить и запушить.

Запрещено на этом шаге: скачивать субтитры, искать транскрипт, запускать `yt-dlp` с любыми ключами субтитров, придумывать теги и содержание по названию.

### 2. «Скачай субтитры: `<ссылка>`»

1. Найти папку ролика (по `video_id` в `README.md` или по ссылке в `INDEX.md`).
2. Скачать командой ниже только оригинальную дорожку. Машинный перевод не качать никогда.
3. Сохранить как `subtitles.<язык-оригинала>.srt` в папке ролика; если yt-dlp отдал `subtitles.<язык>-orig.srt` — переименовать.
4. В `INDEX.md` в строке этого ролика поставить субтитры — «да».
5. Закоммитить и запушить: файл субтитров и `INDEX.md`.

### 3. «Сделай структуру: `<ссылка>`»

1. Прочитать `subtitles.*.srt` этого ролика. Без субтитров структуру не писать.
2. В `README.md` ниже front matter написать структуру: «Коротко» (2–4 предложения), затем нумерованные разделы с содержанием, и при пользе — факты и шаги.
3. В front matter поставить `structure_status: ready` и заполнить `tags` — только то, что подтверждено содержанием.
4. В `INDEX.md` в строке этого ролика поставить структуру — «да» и перенести `tags` в колонку тегов.
5. Закоммитить и запушить: `README.md` и `INDEX.md`.

### 4. «Создай разделы: `<ссылка>`»

Цель команды — не ещё один конспект, а подготовка ролика к содержательному обсуждению. Каждый файл `sections/*.md` должен содержать **полный текст одного смыслово законченного фрагмента**, чтобы Voice/Куратор мог быстро загрузить его целиком и работать с аргументом в полном контексте.

1. Найти папку ролика и прочитать **весь** текст ролика. Без субтитров разделы не создавать. На локальной машине читать не сырой `subtitles.*.srt`, а очищенную расшифровку — она в 4–5 раз меньше при том же содержании, потому что в сыром файле каждая строка повторяется по три-четыре раза (см. «Материализация смысловых разделов»):

   ```bash
   python tools/materialize_sections.py "<папка ролика>" --transcript --out "<временный файл вне репозитория>"
   ```

   Сырой SRT читать целиком только там, где Python недоступен.
2. Определить смысловые границы по ходу мысли автора, а не механически по времени. Предпочитать минимальное число достаточно крупных, самостоятельно обсуждаемых разделов.
3. Размер — мягкий ориентир, а не причина резать мысль: обычно стремиться примерно к 5–10 минутам речи на раздел; законченный аргумент может быть короче, а длинный блок допустимо расширить примерно до 12–15 минут, если внутри нет естественной границы.
4. Разделы должны непрерывно покрывать весь ролик: первый начинается с `00:00:00`, конец каждого равен началу следующего, последний заканчивается `END`. Не оставлять дыр и не создавать смысловых перекрытий.
5. В `README.md` создать или заменить только управляемый блок `## Разделы` между маркерами `<!-- sections:begin -->` и `<!-- sections:end -->`. Существующую структуру, front matter и `review` не переписывать.
6. Каждый раздел обогатить материалом, который модель уже может получить попутно при чтении:
   - точное содержательное название;
   - `Интервал`;
   - `Суть` — 1–3 предложения;
   - `Опорные мысли` — 2–5 пунктов, отражающих ход аргумента, а не общий пересказ;
   - `Для обсуждения` — 0–3 действительно содержательных вопроса, напряжения или места, которые стоит проверить; не выдумывать вопросы ради заполнения;
   - `Темы` — несколько поисковых ключей;
   - ссылка на ожидаемый файл `sections/NN.md`.
7. Формат блока должен быть машинно читаемым скриптом:

   ```markdown
   ## Разделы

   <!-- sections:begin -->

   ### 1. Постановка вопроса о возрасте Земли
   **Интервал:** `00:00:00 --> 00:06:20`
   **Суть:** Автор формулирует конфликт между молодой библейской хронологией и наблюдениями, которые выглядят как свидетельство больших возрастов.
   **Опорные мысли:**
   - Библейская хронология трактуется как несколько тысяч лет от Адама.
   - Свет далёких звёзд используется как основной пример кажущегося большого возраста.
   **Для обсуждения:**
   - Действительно ли обозначенный конфликт следует из самого текста Писания или из конкретной его хронологии?
   **Темы:** `creation`, `age-of-earth`, `starlight`
   **Файл:** [sections/01.md](sections/01.md)

   ### 2. Следующий смысловой блок
   **Интервал:** `00:06:20 --> END`
   **Суть:** ...
   **Опорные мысли:**
   - ...
   **Темы:** `...`
   **Файл:** [sections/02.md](sections/02.md)

   <!-- sections:end -->
   ```

8. Если команда выполняется на локальной машине, после сохранения карты сразу запустить из корня репозитория:

   ```bash
   python tools/materialize_sections.py "<папка ролика>"
   ```

   Скрипт валидирует непрерывность интервалов и создаёт/пересоздаёт `sections/01.md`, `sections/02.md` и т. д. В каждый файл он переносит обогащённое описание из README и затем полный текст соответствующих SRT-cues. Он **не дедуплицирует, не суммаризирует и не переписывает** исходную речь.

9. Если локальной машины нет, допустимо завершить интеллектуальную часть команды: сохранить и закоммитить карту в `README.md`, явно сообщив, что `sections/*.md` ещё не материализованы. Не создавать вручную большие section-файлы в облачной сессии вместо скрипта.
10. Команда «Создай разделы» не меняет `structure_status`, `tags` или строку `INDEX.md`: структура и смысловые разделы — независимые представления одного ролика.
11. Если скрипт был запущен, закоммитить вместе `README.md` и сгенерированные `sections/*.md`. Если была доступна только облачная часть — коммит содержит только карту `README.md`.

## README.md ролика

Единственный файл метаданных и авторской карты содержания. При регистрации:

```yaml
---
title: ""
youtube: ""
video_id: ""
date: ""
collection: ""
structure_status: pending
tags: []
---
```

Ниже front matter — заголовок ролика и одна строка-заглушка до появления структуры или разделов.

### `review` — состояние кураторской проработки

В front matter `README.md` может присутствовать отдельный блок `review`, который ведёт **Куратор ATLAS** при содержательной проработке ролика. Это допустимая часть metadata ролика, а не данные YouTube ingestion/structure pipeline.

Канонический способ заполнения и смысл значений определён в `wlad00/ATLAS` → `ALGORITHMS/youtube-video-review.md`. Здесь фиксируется только граница ответственности.

Форма блока:

```yaml
review:
  stage: discussed
  state: open
  sessions:
    - date: "2026-09-12"
      turns: 12
      minutes: 35
      insights: 3
```

Правила для агентов этого репозитория:

- отсутствие `review` допустимо и означает, что Куратор ещё не начал вести review-метаданные этого ролика;
- команды «прими ролик», «скачай субтитры», «сделай структуру» и «создай разделы» **не создают и не изменяют** `review`;
- если `review` уже существует, при любых обычных правках ролика сохранить его без изменений;
- не удалять, не переименовывать и не нормализовать поля `review.stage`, `review.state`, `review.sessions` как «неизвестные» metadata;
- review-история конкретного ролика канонически хранится здесь, в его `README.md`; ATLAS хранит алгоритм работы и собственные durable выводы, но не дублирует эту статистику.

## INDEX.md

В начале файла находится секция `## Разделы` — актуальный список разделов с краткими описаниями. При добавлении или удалении раздела эту секцию необходимо обновить в том же коммите.

Одна строка на ролик, новые сверху (сортировка по дате, от новых к старым). Шаблон строки:

```text
| ГГГГ-ММ-ДД | [Название](раздел/папка/README.md) | [VIDEO_ID](https://www.youtube.com/watch?v=VIDEO_ID) | `раздел` | нет | нет | — |
```

Если ссылка на YouTube неизвестна — в колонке YouTube ставится `—`.

Источник истины — файлы, а не индекс:

- есть `subtitles.<язык>.srt` → субтитры «да», нет файла → «нет»;
- `structure_status: ready` → структура «да», `pending` → «нет».

Наличие `sections/` в `INDEX.md` пока отдельно не отражается.

Если индекс разошёлся с файлами — править индекс по файлам.

## Неотсортированные ролики

`unsorted/` — раздел для роликов, у которых подходящий раздел неочевиден. Правило простое: сомнение в разделе не повод останавливать работу и спрашивать пользователя. Кладём в `unsorted/` и продолжаем — скачиваем субтитры, делаем структуру или создаём разделы. Разобрать раздел всегда можно потом, а прерванная на вопросе команда стоит пользователю времени.

Перенос из `unsorted/` в настоящий раздел — отдельная команда пользователя: переместить папку и поправить строку в `INDEX.md` (путь и колонку раздела) одним коммитом.

После любой из четырёх команд, если в `unsorted/` есть хотя бы один ролик, в конце ответа одной строкой напомнить: сколько роликов ждёт разбора и что их можно разложить по разделам.

## Скачивание субтитров

`yt-dlp` установлен через winget, но его почти никогда нет в `PATH` сессии. Не проверять `yt-dlp --version`, а сразу запускать по явному пути из корня репозитория.

Маска `--sub-langs "*-orig"` в версии yt-dlp 2026.07.04 сломана — падает с `Wrong regex for subtitlelangs: *-orig` (проверено 2026-09-09). Поэтому сначала узнать код языка оригинала, потом подставить его явно вместо маски:

```powershell
& "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe\yt-dlp.exe" --list-subs "<ссылка>"
```

В выводе найти строку вида `ru-orig  Russian (Original)` — это и есть код языка (`<lang>-orig`) для команды ниже.

PowerShell:

```powershell
& "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe\yt-dlp.exe" --skip-download --write-auto-subs --write-subs --sub-langs "<lang>-orig" --convert-subs srt --no-progress --ffmpeg-location "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.FFmpeg_Microsoft.Winget.Source_8wekyb3d8bbwe\ffmpeg-N-125875-g5d4d3bdc61-win64-gpl\bin" -o "<папка ролика>/subtitles.%(ext)s" "<ссылка>"
```

Bash — тот же бинарник, но путь в POSIX-виде и без `&`:

```bash
"$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe/yt-dlp.exe" --skip-download --write-auto-subs --write-subs --sub-langs "<lang>-orig" --convert-subs srt --no-progress --ffmpeg-location "$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.FFmpeg_Microsoft.Winget.Source_8wekyb3d8bbwe/ffmpeg-N-125875-g5d4d3bdc61-win64-gpl/bin" -o "<папка ролика>/subtitles.%(ext)s" "<ссылка>"
```

`--ffmpeg-location` обязателен: без него `--convert-subs srt` падает с `ffmpeg not found`.

`--no-progress` убирает полосу загрузки: вместо десятка строк с процентами и скоростью остаётся одна строка о завершении. На одном ролике это мелочь, на пачке из десятка — заметная доля вывода, поэтому ключ не убирать.

Если маску всё же попробовать по старой памяти и она снова заработает в новой версии yt-dlp — можно вернуться к `"*-orig"` и убрать шаг с `--list-subs`; до тех пор явный код языка надёжнее.

### Переименование после скачивания

Файл всегда приезжает как `subtitles.<язык>-orig.srt`. Это не ошибка команды: `*-orig` — код, которым YouTube обозначает оригинальную авто-дорожку (в отличие от `<язык>` без суффикса — машинного перевода), а yt-dlp вставляет код языка в имя файла сам, после шаблона `-o`. Отключить это опциями нельзя, поэтому переименование — обязательный второй шаг, а не ручная доводка.

PowerShell:

```powershell
Get-ChildItem "<папка ролика>\subtitles.*-orig.srt" | Rename-Item -NewName { $_.Name -replace '-orig\.srt$', '.srt' }
```

Bash:

```bash
for f in "<папка ролика>"/subtitles.*-orig.srt; do mv "$f" "${f%-orig.srt}.srt"; done
```

В папке ролика должен остаться ровно один файл субтитров — без суффикса `-orig`.

Проверка доступа тем же бинарником (печатает заголовок — значит сеть в порядке): `--simulate --print "%(title)s" "<ссылка>"`.

Если `*-orig` ничего не нашёл — у видео ручные субтитры: посмотреть `--list-subs` и взять дорожку оригинала без `-orig`.

### Диагностика: увидел → сделай

- `yt-dlp: command not found` — пустой `PATH`, а не «программы нет» и не блокировка сети. Запустить по явному пути выше.
- `HTTP Error 429: Too Many Requests` — лимит по IP, смена инструмента не поможет. Подождать несколько минут и повторить, не гнать запросы подряд.
- `Sign in to confirm you're not a bot` — добавить `--cookies-from-browser chrome`, предварительно закрыв Chrome. Для публичных видео куки не нужны.
- Предупреждение `No supported JavaScript runtime` на субтитры не влияет. Если станет ошибкой — deno установлен: `--js-runtimes "deno:$env:LOCALAPPDATA\Microsoft\WinGet\Packages\DenoLand.Deno_Microsoft.Winget.Source_8wekyb3d8bbwe\deno.exe"` (путь только в Windows-формате; проверено 2026-08-29).
- Скачивание работает только в локальной сессии на машине пользователя. В облачной сессии нет ни `yt-dlp`, ни файлов репозитория — сообщить пользователю, а не обходить.
- Не получать субтитры через браузер, WebFetch или веб-поиск: это упирается в прокси и создаёт ложный вывод «YouTube недоступен» (у `yt-dlp` прямой доступ есть, проверено 2026-08-29).

## Материализация смысловых разделов

`tools/materialize_sections.py` работает только с локальной копией репозитория и использует только стандартную библиотеку Python.

Запуск из корня репозитория:

```bash
python tools/materialize_sections.py "<папка ролика>"
```

Скрипт:

- находит ровно один `subtitles.*.srt`;
- читает управляемый блок `<!-- sections:begin --> ... <!-- sections:end -->` из `README.md`;
- проверяет последовательную нумерацию, начало с `00:00:00`, непрерывность границ и `END` только у последнего раздела;
- назначает каждый SRT-cue ровно одному разделу по времени начала cue;
- сохраняет исходный текст cue как есть, включая повторы rolling captions; специальной дедупликации нет;
- переносит в начало section-файла обогащённое описание раздела из README;
- пересоздаёт только сгенерированные `sections/NN.md`.

`sections/` считается generated-only: собственные заметки и durable выводы туда не помещать.

### Очищенная расшифровка для чтения

Тот же скрипт с ключом `--transcript` ничего не создаёт в репозитории, а выдаёт расшифровку ролика для чтения: повторы «ползущих» субтитров YouTube склеены, метки времени сохранены. Нужен на шаге «создай разделы», чтобы размечать границы, не загружая сырой SRT.

```bash
python tools/materialize_sections.py "<папка ролика>" --transcript --out "<временный файл вне репозитория>"
```

- `--out` лучше указывать всегда: в Windows-консоли кириллица в stdout портится;
- файл расшифровки временный и в репозиторий не коммитится — сырой SRT остаётся единственным источником истины;
- `--window` задаёт, сколько секунд текста идёт под одной меткой времени (по умолчанию 30);
- на границы разделов это не влияет: `sections/*.md` всё равно собираются из сырого SRT.

## Коммит и пуш

После каждой из четырёх команд изменения сразу коммитятся и пушатся в `main` — отдельного разрешения спрашивать не нужно, это часть шага. Один пользовательский шаг — один итоговый коммит, если технически возможно.

```bash
git add -A
```

```bash
git commit -m "<что сделано>"
```

```bash
git push origin main
```

Если пуш отклонён из-за расхождения — сначала `git pull --rebase origin main`, затем повторить пуш.

## Прочее

- Язык в имени файла — всегда фактический язык оригинальной дорожки: `subtitles.ru.srt`, `subtitles.uk.srt`, `subtitles.en.srt`.
- Video ID не использовать как имя папки.
