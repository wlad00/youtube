# AGENTS.md

Репозиторий с YouTube-роликами, очищенными расшифровками, выжимками и навигацией для последующего обсуждения.

## Главная модель

Один ролик = одна папка = один основной текстовый источник.

    <коллекция[/подколлекция...]>/<ГГГГ-ММ-ДД-slug-названия>/
      README.md
      transcript.cleaned.md
      SUMMARY.md           # выжимка: появляется при подготовке
      sections.yaml        # только у длинного ролика: границы разделов
      sections/            # только у длинного ролика: текст разделов отдельными файлами
      INSIGHTS.md          # опционально, только выводы реального обсуждения

Если известен только месяц публикации — ГГГГ-ММ-slug-названия.

Короткий ролик — transcript.cleaned.md до 40 000 знаков. Длинный — больше. Считать знаки, а не байты: длина текста, прочитанного как UTF-8 (len в Python); wc -c и размер файла дают байты и завышают кириллицу примерно вдвое. Порог выбран по тому, что умещается в контекст обсуждения на ChatGPT.com целиком; длинный ролик там целиком не загружается, поэтому режется на разделы.

У старых роликов могут оставаться дополнительные файлы, поля и блоки прежнего формата: блоки ## Кратко и ## Навигация в шапке transcript.cleaned.md, chunks/, sections/ без SUMMARY.md. Не удалять их автоматически и не строить на них новый рабочий процесс.

### transcript.cleaned.md

transcript.cleaned.md — обязательная цельная очищенная расшифровка и единственный первичный источник содержания ролика.

    [00:00:03] Полный текст расшифровки...
    [00:00:33] ...

Полный текст не переписывать. Служебных блоков в шапке у новых роликов нет: выжимка и навигация живут в SUMMARY.md. У старых роликов шапка ## Кратко / ## Навигация допустима; парсер tools/materialize_sections.py игнорирует Markdown до первой строки с таймкодом.

### SUMMARY.md

SUMMARY.md — выжимка ролика для начала обсуждения и для поиска нужного места. Это пересказ, а не источник фактов: любой конкретный факт, число, имя, цитата или довод при ответе берётся из текста по таймкоду.

    # Название ролика

    ## Кратко

    Абзац 5–8 предложений или 3–5 тезисов-утверждений с итоговым выводом.

    ## Разделы

    ### 1. Название раздела — 00:00:00–00:09:40
    Абзац 3–6 предложений о содержании раздела.
    Файл: sections/01.md

    ### 2. ...

    Выжимка — пересказ. Факты, числа и цитаты брать из текста по таймкоду.

Правила:

- Кратко — содержательная выжимка, не список тем: позиция автора, ход мысли, вывод. Проверка: прочитав только Кратко, можно пересказать ролик собеседнику и назвать, с чем в нём можно спорить.
- Раздел — свой абзац 3–6 предложений: что говорится, какие аргументы и примеры, какие имена, числа, места Писания или источники упоминаются; если внутри раздела заметный поворот — его таймкод. Проверка: по абзацу понятно, в каком разделе искать ответ на любой вопрос по ролику.
- Имена и числа в выжимке — указатели, где искать, а не факты для ответа. Дословных цитат в выжимке не писать, чтобы их нельзя было выдать за текст.
- Строка «Файл: sections/NN.md» — только у длинного ролика. У короткого разделы — навигация по таймкодам внутри цельного транскрипта.
- Объём: короткий ролик 4–8 разделов по 400–600 знаков, всего 3–5 тыс. знаков; длинный 6–12 разделов по 600–900 знаков, всего 6–10 тыс. знаков.
- Последняя строка файла — предупреждение, как в образце.

### Разделы: sections.yaml и sections/

Только для длинного ролика. Границы выбирает модель по смыслу, текст режет скрипт из transcript.cleaned.md.

    sections:
      - title: "Название раздела"
        start: "00:00:00"
        end: "00:09:40"
      - title: "Следующий раздел"
        start: "00:09:40"
        end: "END"

Правила границ:

- Один раздел = одна мысль автора, 5–10 тыс. знаков, примерно 8–15 минут речи. Меньше 3 тыс. знаков — склеить с соседом, даже если тема сменилась. Больше 12 тыс. — искать подграницу внутри.
- Границу ставить в начале переходной фразы автора, чтобы раздел открывался собственным анонсом, а не хвостом предыдущей темы.
- Не дробить механически по равным интервалам.
- Номера разделов в SUMMARY.md и sections.yaml совпадают.

Материализация:

    python tools/materialize_sections.py "<папка ролика>"

Скрипт создаёт sections/NN.md с интервалом в шапке и записывает в README.md блок «Разделы» со ссылками между маркерами sections. Этот блок — побочный продукт скрипта, не редактировать руками. Разделы без перехлёста: каждая строка транскрипта попадает ровно в один файл; стыки закрывает правило соседа при обсуждении.

Нарезка возможна только в среде со скриптом (Desktop/local). На ChatGPT.com разделы не создавать вручную.

### README.md

README.md хранит метаданные ролика, а не пересказ.

Новый front matter:

    ---
    title: ""
    youtube: ""
    video_id: ""
    date: ""
    collection: ""
    author: ""
    channel: ""
    language: ""
    tags: []
    ---

Ниже front matter — заголовок ролика. Не помещать туда Кратко, навигацию, пересказ, тезисы или выводы. У длинного ролика ниже заголовка стоит блок «Разделы», который пишет скрипт нарезки.

Если в старом README уже есть неизвестные/legacy-поля или блок review, сохранять их без изменений, если текущая команда прямо не относится к ним.

### INSIGHTS.md

INSIGHTS.md — опциональный файл для durable-выводов реального обсуждения. Не создавать его во время скачивания или подготовки ролика и не использовать как замену транскрипту.

Открывать его только когда пользователь просит продолжить прошлое обсуждение, вспомнить прежние выводы или сохранить новые выводы.

## INDEX.md

INDEX.md — единый каталог роликов. Первичный поиск по автору, каналу, коллекции, названию, описанию и тегам начинать с него. Для защиты от дублей Video ID считается уникальным идентификатором ролика: один Video ID должен соответствовать одной строке INDEX и одной папке ролика.

Таблица:

    | Дата | Ролик | Автор | Канал | YouTube | Коллекция | Субтитры | Подготовлен | О чём | Теги |

Правила:

- Автор — человек/ведущий/автор ролика, если он однозначно известен без анализа всего содержания. Для авторской коллекции брать каноническое имя автора из самой коллекции. Если автор неочевиден, ставить — и при необходимости уточнять во время подготовки.
- Канал — точное название YouTube-канала из метаданных yt-dlp. Записывать сразу при приёме ролика; это не требует чтения транскрипта.
- Автор и Канал — базовые метаданные и не зависят от статуса подготовки.
- Субтитры = да, если существует transcript.cleaned.md.
- Подготовлен = да, только если существует SUMMARY.md, а для длинного ролика ещё и sections/. Старая шапка ## Кратко / ## Навигация в транскрипте подготовкой не считается.
- О чём — одно короткое предложение, полученное после чтения всего транскрипта. До подготовки ставить —. У роликов, подготовленных по старой схеме, уже заполненные О чём и Теги сохранять: они получены из чтения транскрипта.
- Теги берутся из tags в front matter README.md. До подготовки могут быть —.
- Источник истины — файлы ролика; если INDEX расходится с ними, исправлять INDEX по файлам.
- Новые ролики добавлять сверху по дате.
- Перед созданием новой строки обязательно проверить INDEX по точному Video ID. Если такой ID уже есть, новую строку не создавать.

В начале INDEX находится список коллекций с короткими описаниями.

## Защита от дублей

Эта проверка обязательна перед любым приёмом, скачиванием или полным pipeline.

1. Сначала получить точный YouTube Video ID из ссылки или метаданных.
2. До создания папки, README, строки INDEX и до скачивания субтитров найти этот Video ID в INDEX.md.
3. Если ID уже есть:
   - перейти в существующую папку из строки INDEX;
   - не создавать новую папку и не добавлять вторую строку;
   - если transcript.cleaned.md уже существует, не скачивать субтитры повторно;
   - если транскрипта нет, скачать и очистить субтитры в существующую папку;
   - если ролик уже подготовлен, не повторять подготовку без явной причины или команды пользователя.
4. Если ID в INDEX отсутствует, дополнительно проверить README.md по репозиторию на exact video_id — это защита от случая, когда папка уже есть, а INDEX устарел. Если найден существующий README, восстановить/исправить строку INDEX и использовать эту папку.
5. Только если Video ID нигде не найден, создавать новую папку и новую строку INDEX.
6. Название ролика не использовать как уникальный ключ: оно может измениться. Основной ключ дедупликации — Video ID.

## Основные команды

Перед изменениями в локальной сессии выполнить:

    git pull --rebase origin main

Правки могут прийти из другой сессии или через GitHub.

### 1. «Прими ролик: <ссылка>»

Ссылку можно заменить названием, автором, примерной датой, фразой из ролика или другими однозначными признаками.

Если ссылки нет, искать YouTube через yt-dlp:

    "$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe/yt-dlp.exe" --simulate --print "%(title)s | %(channel)s | %(upload_date)s | %(id)s" "ytsearch10:<запрос>"

Если совпадение одно — брать его. Если кандидатов несколько — показать название, канал, дату и ID и дать выбрать.

Дальше:

1. Получить название, каноническую ссылку, Video ID, дату публикации и точное название YouTube-канала.
2. Немедленно выполнить обязательную проверку дублей по Video ID.
3. Если ролик уже существует, использовать найденную папку и привести её метаданные/INDEX в актуальное состояние; новый экземпляр не создавать.
4. Только для нового Video ID выбрать коллекцию по теме; при неоднозначности использовать unsorted/, не останавливая работу. Если коллекция авторская, сразу определить каноническое имя автора. Для неавторской коллекции записывать автора только если он однозначно известен из метаданных/названия без анализа всего ролика.
5. Для нового ролика создать папку и README.md по новому шаблону; сразу заполнить author и channel, насколько они объективно известны.
6. Для нового ролика добавить одну строку в INDEX.md, сразу указав Автор и Канал; Субтитры — нет, Подготовлен — нет, О чём — —, Теги — —.
7. Commit + push.

На этом шаге не придумывать содержание по одному названию.

### 2. «Скачай субтитры: <ролик>»

1. Получить/уточнить Video ID и выполнить обязательную проверку дублей.
2. Найти единственную существующую папку этого Video ID. Если transcript.cleaned.md уже существует, повторно не скачивать субтитры: синхронизировать INDEX при необходимости и завершить технический шаг.
3. Если cleaned-транскрипта ещё нет, скачать только оригинальную дорожку; машинный перевод не использовать.
4. Записать фактический язык оригинала в language README. Если channel или author ещё пусты, заполнить их из доступных метаданных/авторской коллекции без содержательного анализа.
5. Из сырого SRT обязательно создать transcript.cleaned.md с дедупликацией rolling captions и сохранением таймкодов.
6. Удалить сырой subtitles.*.srt после успешного создания cleaned-файла.
7. Не создавать автоматически SUMMARY.md, sections.yaml, sections/ или INSIGHTS.md.
8. В INDEX.md синхронизировать Автор и Канал из README, поставить Субтитры — да; оставить Подготовлен — нет, если аналитическая подготовка ещё не выполнялась.
9. Commit + push.

Это дешёвый технический ingestion. Он не должен автоматически читать и анализировать весь ролик.

### 3. «Подготовь ролик: <ролик>»

Эквивалентные команды:

- «Подготовь ролик»
- «Подготовь к обсуждению»
- «Подготовь видео»

Результат подготовки — SUMMARY.md, а для длинного ролика ещё sections.yaml и sections/. Стоимость подготовки — одно чтение всего транскрипта; всё остальное — небольшой вывод и запуск скрипта.

### Подагент для подготовки

Если в Codex доступен глобальный подагент `video_preparer`, аналитическую подготовку ролика **обязательно делегировать ему**.

`video_preparer` выполняет содержательную часть подготовки: читает весь `transcript.cleaned.md`, пишет `SUMMARY.md`, для длинного ролика — `sections.yaml`, определяет теги, одно предложение «О чём» и при необходимости уточняет `author`.

Основной агент оставляет за собой только оркестрацию и технические действия: проверку Video ID и дублей, поиск папки, проверку наличия транскрипта и его размера, запуск скрипта нарезки, синхронизацию README/INDEX, commit и push.

- В поручении подагенту называть: путь к ролику, короткий он или длинный, и что именно он должен создать по этому файлу (SUMMARY.md и правила выжимки; для длинного — sections.yaml и правила границ). Инструкции подагента в глобальной конфигурации Codex могут отставать от этого файла; поручение имеет приоритет.
- Не заменять `video_preparer` более тяжёлым подагентом только из-за длины транскрипта.
- Не создавать дополнительных подагентов для этой же аналитической подготовки.
- Настройки модели и reasoning effort для `video_preparer` задаются в глобальной конфигурации Codex; этот репозиторий их не переопределяет.
- Если `video_preparer` недоступен в текущей среде, выполнить ту же процедуру основным агентом как fallback, не меняя формат результата.

Алгоритм:

1. Найти папку ролика.
2. Проверить наличие transcript.cleaned.md.
3. Если его нет:
   - в локальной/Desktop-среде, где доступен yt-dlp, сначала выполнить шаг «Скачай субтитры»;
   - в среде без локального доступа к yt-dlp не выдумывать содержание: сообщить, что сначала нужно получить cleaned-транскрипт.
4. Определить размер транскрипта в знаках (не байтах): до 40 000 — короткий ролик, больше — длинный. Длинный ролик готовить только в среде со скриптом нарезки; на ChatGPT.com сообщить, что нужна локальная подготовка.
5. Если доступен `video_preparer`, передать ему путь к ролику, его тип и поручить пункты 6–10; основной агент не дублирует его аналитический проход. Если подагент недоступен — выполнить пункты 6–10 самостоятельно.
6. Прочитать весь transcript.cleaned.md от начала до конца.
7. Определить разделы по правилам раздела «Разделы: sections.yaml и sections/»: смысловые границы, размер, граница в начале переходной фразы. Для короткого ролика это 4–8 разделов-якорей без файлов; для длинного — 6–12 разделов, записать их в sections.yaml.
8. Написать SUMMARY.md по образцу и правилам из раздела «SUMMARY.md»: содержательное Кратко, абзац на каждый раздел, у длинного ролика — строка «Файл: sections/NN.md», последней строкой — предупреждение.
9. Если author был неизвестен и стал однозначен после чтения ролика, заполнить/уточнить author. Не менять channel без причины: это точное поле метаданных YouTube.
10. Выбрать примерно 3–8 полезных тегов и записать их в tags README; сформулировать одно короткое предложение О чём для общего INDEX.
11. Для длинного ролика основной агент запускает скрипт нарезки и проверяет, что число файлов в sections/ совпадает с числом разделов в SUMMARY.md.
12. Обновить строку INDEX: синхронизировать Автор и Канал, Субтитры — да, Подготовлен — да, заполнить О чём и Теги.
13. Commit + push.

Команда идемпотентна: повторный запуск обновляет SUMMARY.md, sections.yaml и sections/, а не создаёт дубликаты. Старую шапку ## Кратко / ## Навигация в transcript.cleaned.md при переподготовке можно использовать как заготовку границ; удалять её не обязательно.

Полный текст расшифровки не переписывать.

### 4. «Прими и подготовь ролик: <ссылка>»

Универсальный полный pipeline:

    получить Video ID → проверить дубликат →
    принять только если нового ID ещё нет →
    скачать субтитры только если transcript.cleaned.md отсутствует →
    очистить → определить короткий/длинный →
    video_preparer: прочитать целиком → разделы → SUMMARY.md →
    sections.yaml для длинного → автор при необходимости → теги → О чём →
    основной агент: нарезка для длинного → обновить INDEX → commit + push

В Desktop/local выполнять целиком.

В ChatGPT.com, если transcript.cleaned.md уже есть в репозитории и ролик короткий, команда начинает с аналитической подготовки. Если транскрипта ещё нет и локальный yt-dlp недоступен, либо ролик длинный, остановиться на недостающем техническом шаге и явно это сказать.

### Голая ссылка без команды

Голая ссылка на YouTube означает:

    получить Video ID → проверить дубликат → Прими ролик + Скачай субтитры при необходимости

Если Video ID уже зарегистрирован, второй экземпляр не создаётся. Если cleaned-транскрипт уже существует, он не скачивается заново. Полный аналитический проход автоматически не запускается.

Если пользователь хочет всё за один раз, он говорит: «Прими и подготовь ролик».

Исключение из правила голой ссылки: если в том же сообщении после ссылки стоит «п» или «подготовь», это то же самое, что «Прими и подготовь ролик» — полный проход запускается.

## Тематический навигатор и учёт обсуждений

Для запросов о **разделах** репозитория, их темах, о том, что уже изучено и что осталось, использовать [TOPICS_PROGRESS.md](TOPICS_PROGRESS.md). Это отдельный от INDEX и `review` в README ручной учёт.

**Единая терминология тематического навигатора:**
- **Раздел** — глобальное направление репозитория (например, «2. Искусственный интеллект и модели»).
- **Тема** — конкретный вопрос внутри раздела (например, «2.3. AGI, сверхразум и прогнозы развития ИИ»). В разговоре и в трекере использовать «раздел → темы», а не «глобальная тема → подраздел» или «раздел → подтемы».
- Это **не** технические разделы одного ролика, хранящиеся в `sections.yaml` и `sections/`. Для них слово «раздел» по-прежнему допустимо в контексте конкретного видео.

**Интерес, обзор, заметки, статусы:**
- Для каждого раздела можно указать **интерес 1–10** и **уровень просмотра и обсуждения 1–10**, а также **заметки** с личными выводами пользователя. В обеих оценках пользователь выбирает балл сам; не выставлять их по предположениям. Для отдельной темы оценки можно вести отдельно. Если оценка ещё не выставлена, показывать `—` (не 0).
- Ориентиры для уровня обсуждения: 1–2 — краткое знакомство; 3–4 — начальный разбор; 5–6 — разбор ключевых материалов и позиций; 7–8 — подробный анализ; 9–10 — глубокая проверка и выводы. **Это субъективный балл, а не доля завершённых тем.** После перехода со шкалы 0–4 ранее выставленные пользователем числа сохраняются (например, 2/4 записываем как 2/10), а не пропорционально пересчитываются; согласованные оценки доступны в `TOPICS_PROGRESS.md`.
- **«Раздел закрыт на текущем этапе»** означает, что пользователь закончил его обсуждать **сейчас**, а не что изучены все темы, просмотрены все ролики или получена максимальная оценка. Сохранять текущие оценки и заметки, незавершённые темы не отмечать `[x]`; по желанию пользователя раздел открывается снова.
- Разделы и темы перечислены в `TOPICS_PROGRESS.md`; один ролик может относиться к нескольким направлениям.
- Составлять каталог или читать `SUMMARY.md` не означает, что тема изучена или видео просмотрено.
- После **содержательного обсуждения** темы с опорой на исходные транскрипты/разделы роликов обновить в этом файле журнал (дата, выводы, источники, Video ID), состояние темы и счётчик полностью проработанных тем. Частичное обсуждение отметить «в работе» либо «обзор закрыт на текущем этапе» по решению пользователя, не засчитывая завершение полного разбора.
- Счётчик изученных роликов по теме — уникальные Video ID, реально проработанные по первичному тексту и зафиксированные в журнале; не путать с физическим просмотром на YouTube, статусом подготовки и кураторским `review`.
- Старые обсуждения не объявлять «непройденными»: нули трекера — это только новый учёт с 2026-10-22.

## Обсуждение ролика

Первичный источник содержания — текст с таймкодами: transcript.cleaned.md у короткого ролика, sections/NN.md у длинного. SUMMARY.md — карта и стартовая точка разговора, не источник фактов.

Когда пользователь начинает содержательно обсуждать ролик:

1. Открыть SUMMARY.md. Дать обзор по нему; в голосовом режиме озвучивать Кратко, список разделов — по запросу.
2. Если SUMMARY.md нет, один раз предложить: «Ролик ещё не подготовлен к обсуждению. Подготовить?» Не блокировать разговор: если пользователь хочет ответ сразу, работать по полному транскрипту без подготовки.
3. Обзорные вопросы — о чём ролик, что автор думает в целом, с чего начать — можно отвечать по выжимке, помечая это: «по выжимке».
4. Конкретный вопрос — что именно сказано, какие числа, имена, цитаты, ход аргумента — только по тексту:
   - короткий ролик: открыть transcript.cleaned.md и прочитать фрагмент по таймкоду раздела из выжимки плюс достаточный контекст до/после;
   - длинный ролик: открыть раздел по номеру из выжимки. Весь транскрипт не загружать.
5. Правило соседа: если вопрос попадает в первые или последние две минуты раздела, прочитать и соседний раздел. Границы видны в выжимке и в шапке файла раздела.
6. Доказательство чтения: каждый конкретный факт в ответе сопровождается таймкодом строки, из которой он взят, и при необходимости короткой дословной цитатой. Таймкод начала раздела доказательством не является: он есть в выжимке. Ответ на конкретный вопрос без строчных таймкодов означает, что модель осталась в выжимке.
7. «Упоминал ли автор X» — поиск по тексту разделов или транскрипта, не по выжимке.
8. Не отвечать на конкретные фактические вопросы только по SUMMARY.md.
9. Для вопросов, связывающих начало, середину и конец ролика, по выжимке выбрать нужные разделы, прочитать каждый и сверить ответ по первичному тексту.
10. У старых роликов без SUMMARY.md, но с шапкой ## Кратко / ## Навигация в транскрипте, использовать шапку как карту по тем же правилам; у старых роликов с sections/ без SUMMARY.md — читать разделы по README-блоку «Разделы».

## review — состояние кураторской проработки

В front matter README может присутствовать блок review, который ведёт Куратор ATLAS. Это отдельная ответственность.

    review:
      stage: discussed
      state: open
      sessions:
        - date: "2026-09-12"
          turns: 12
          minutes: 35
          insights: 3

Обычные команды YouTube-pipeline не создают, не удаляют и не нормализуют review. Если он существует, сохранять его без изменений.

## Неотсортированные ролики

unsorted/ — временная коллекция для роликов, у которых тематическая коллекция неочевидна. Сомнение не должно останавливать ingestion или подготовку.

Перенос из unsorted/ — отдельная команда: переместить папку и в том же коммите поправить путь и колонку Коллекция в INDEX.

После основной команды, если в unsorted/ есть ролики, можно одной строкой напомнить, сколько их ждёт распределения.

## Скачивание субтитров

yt-dlp установлен через winget, но его почти никогда нет в PATH. Не проверять yt-dlp --version; запускать по явному пути.

Сначала узнать код оригинальной дорожки:

    & "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe\yt-dlp.exe" --list-subs "<ссылка>"

Найти строку вида ru-orig  Russian (Original). Маска *-orig в версии yt-dlp 2026.07.04 была сломана, поэтому использовать явный код языка.

PowerShell:

    & "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe\yt-dlp.exe" --skip-download --write-auto-subs --write-subs --sub-langs "<lang>-orig" --convert-subs srt --no-progress --ffmpeg-location "$env:LOCALAPPDATA\Microsoft\WinGet\Packages\yt-dlp.FFmpeg_Microsoft.Winget.Source_8wekyb3d8bbwe\ffmpeg-N-125875-g5d4d3bdc61-win64-gpl\bin" -o "<папка ролика>/subtitles.%(ext)s" "<ссылка>"

Bash:

    "$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe/yt-dlp.exe" --skip-download --write-auto-subs --write-subs --sub-langs "<lang>-orig" --convert-subs srt --no-progress --ffmpeg-location "$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.FFmpeg_Microsoft.Winget.Source_8wekyb3d8bbwe/ffmpeg-N-125875-g5d4d3bdc61-win64-gpl/bin" -o "<папка ролика>/subtitles.%(ext)s" "<ссылка>"

--ffmpeg-location обязателен.

После скачивания файл обычно имеет вид subtitles.<язык>-orig.srt; переименовать без -orig.

PowerShell:

    Get-ChildItem "<папка ролика>\subtitles.*-orig.srt" | Rename-Item -NewName { $_.Name -replace '-orig\.srt$', '.srt' }

Bash:

    for f in "<папка ролика>"/subtitles.*-orig.srt; do mv "$f" "${f%-orig.srt}.srt"; done

Затем создать cleaned-транскрипт:

    python tools/materialize_sections.py "<папка ролика>" --transcript --out "<папка ролика>/transcript.cleaned.md"

Название скрипта историческое. На шаге скачивания использовать его только с --transcript для очистки субтитров. Нарезка на разделы тем же скриптом без флагов — шаг подготовки длинного ролика, не скачивания.

После успешной очистки удалить сырой SRT.

Пакетный режим (список роликов) — `tools/download_subs.py`, запуск и формат списка — в его шапке; папка с «/» на конце во втором поле списка — имя ролика (дата + транслит оригинального названия) скрипт строит сам.

### Диагностика

- yt-dlp: command not found — пустой PATH; использовать явный путь выше.
- HTTP Error 429: Too Many Requests — подождать несколько минут и повторить.
- Sign in to confirm you're not a bot — добавить --cookies-from-browser chrome, предварительно закрыв Chrome.
- Предупреждение No supported JavaScript runtime обычно не мешает субтитрам.
- Скачивание через yt-dlp работает только в локальной среде, где есть программа и сетевой доступ. В облачной сессии не обходить это браузерным скачиванием субтитров.
- Если <lang>-orig отсутствует, посмотреть --list-subs и выбрать ручную дорожку оригинального языка.
- Если у ролика есть сразу en-orig и ru-orig (или другая пара), en-orig может быть машинным переводом, помеченным как оригинал. Перед выбором скачать начало обеих дорожек и взять ту, на языке которой реально звучит речь; её же записать в language.

Проверка доступа:

    "$LOCALAPPDATA/Microsoft/WinGet/Packages/yt-dlp.yt-dlp_Microsoft.Winget.Source_8wekyb3d8bbwe/yt-dlp.exe" --simulate --print "%(title)s" "<ссылка>"

## Legacy: chunks

chunks/ — техническая нарезка прежнего формата, последовательные куски примерно по 6000 знаков без смысловых границ. Новые chunks/ не создавать: длинные ролики закрывают разделы sections/. Существующие chunks/ не удалять автоматически.

    python tools/materialize_sections.py "<папка ролика>" --chunks

## Планы

Общее для Claude и Codex.

- Реестр — [PLANS.md](PLANS.md) в main: план, файл плана, ветка, рабочая папка, статус (в процессе / ждёт решения / готов). Новый план — строка в реестр.
- «Покажи планы» — по каждой строке прочитать PLAN.md из его ветки (`git show <ветка>:<путь>`, вместе с PLAN.md тем), посчитать ролики по статусам: готово / скачано без выжимки / не начато / прочее. Колонки «Субтитры / Подготовлен»: да/да — готово, да/нет — скачано без выжимки, нет/нет — не начато. Показать таблицей: план, ветка, статус, готово/всего, осталось.
- Папка плана — `git worktree` ветки плана с частичной выгрузкой: `git sparse-checkout set <папка автора> tools` (файлы корня выгружаются сами). Лежит рядом с основной папкой: `<основная>-plans/<план>`. Создаётся при первом взятии плана на этой машине, удаляется после слияния ветки в main. Колонка «Рабочая папка» в реестре — папки этого компьютера; на другой машине — своя папка по этому правилу. Чужих авторов в папке плана нет — дубли проверять по INDEX.md.
- «Возьми в работу план X» — работать в ветке и папке плана; каждый ролик отмечать в PLAN.md этой ветки; коммит и push в эту ветку, не в main. Темы — по порядку строк таблицы тем в PLAN.md автора: порядок и есть приоритет.
- «Скачай субтитры по плану X» — ветка и рабочая папка из PLANS.md; из PLAN.md ветки список роликов «не начато» в TSV во временной папке (Video ID, папка ролика от корня репо); `python tools/download_subs.py <список> <рабочая папка>` — одной фоновой командой, без подагента, не опрашивать (сам коммитит и пушит каждые 20 роликов, журнал — `<список>.log`). После окончания — статусы «скачано без выжимки» в PLAN.md по журналу, коммит и push, итог цифрами.
- Затык одного ролика (спорное решение, нет субтитров или ссылки, ролик удалён) — пометить в PLAN.md с причиной и продолжать; вопросы — списком в конце работы. Общий затык (YouTube блокирует, нет сети, лимит модели) — 2–3 повтора, потом стоп с отчётом.
- План закончен — статус «готов» в реестре в main.

## Коммит и пуш

После каждой команды, которая изменила репозиторий, изменения сразу коммитить и пушить в main, без отдельного запроса разрешения.

Если один пользовательский запрос включает полный pipeline, по возможности сделать один итоговый коммит.

    git add -A
    git commit -m "<что сделано>"
    git push origin main

Если push отклонён из-за расхождения:

    git pull --rebase origin main
    git push origin main

## Прочее

- author — имя человека/ведущего, когда оно однозначно известно; channel — точное название YouTube-канала из метаданных.
- Язык в language — фактический язык оригинальной дорожки: например ru, uk, en.
- Video ID не использовать как имя папки.
- Не придумывать содержание ролика по названию, превью или старому вторичному описанию, когда доступен транскрипт.
